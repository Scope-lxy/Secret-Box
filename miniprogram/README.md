# Miniprogram

这里是轻读手记的正式版候选源码，也是 Admin 上传微信开发版时读取的源码。代码仓库状态不代表微信开发版、体验版或正式版已发布；发布状态以微信公众平台为准。

## 开发入口

- 接入、上传和生产运行：`../admin/docs/deployment-1panel.md`的“小程序接入、上传和发布”章节。

用微信开发者工具直接打开本目录；环境、多个 AppID 接入、Admin 上传和上传前检查以上述部署手册章节为准。

### 开发版数据源

- 微信开发版可以在“我的”页开发工具中选择“本地服务器”或“正式服务器”；本地服务器固定为 `http://127.0.0.1:3000/api`，使用前需在 `admin/server` 启动 `npm run dev`。
- `project.config.json` 和本机 `project.private.config.json` 均关闭开发期合法域名校验，使微信开发者工具能够请求本机 HTTP 地址。该设置只服务于本地调试。
- 体验版和正式版无论本地曾选择什么数据源，都会强制使用 `https://secretbox.scopeview.cn/api`，不会读取开发版的数据源选择。
- 微信公众平台中的服务器域名、业务域名和其他发布配置仍是线上状态的唯一真源；关闭开发者工具的域名校验不能替代公众平台配置。

## 数据范围客户端行为

- 小程序通过 `GET /api/miniapp/config` 取得服务端当前的 `dataScopeId`，并按环境和 AppID 分开缓存。
- 创建会话和所有用户数据写请求都携带 `x-miniapp-data-scope`。服务端返回 `409 DATA_SCOPE_CHANGED` 时，本次写入已被拒绝且没有副作用；客户端刷新范围后提示用户重试，不自动重放被拒绝的操作。
- `App.onShow` 每次回到前台都会刷新 `dataScopeId`。如果范围已变化，小程序会清理旧范围的资源缓存和离线队列，然后重新打开当前页面。
- 如果 Admin 在小程序持续停留前台时切换数据模式，当前页面可能暂时显示旧缓存。下一次受保护写入会被 `409` 拒绝并触发范围刷新，不会把数据写入错误范围。

当前客户端与后端必须配套发布，没有旧客户端兼容层。不支持 `x-miniapp-data-scope` 的旧客户端仍可能读取公开数据，已有效会话的受保护读请求也可能成功；但无法创建新会话，也无法执行受数据范围保护的写操作。

留言采用客户端 fail-closed：只有服务端配置明确返回 `messagesEnabled: true` 时才展示；配置缺失、请求失败或审核实例关闭时均默认隐藏。Admin 保留远程启停能力，当前审核实例配置为关闭。审核提交和实际上线配置必须一致，不能依赖审核期间临时隐藏来规避审核。

## 内容列表刷新与排序

文章和心笺列表分别读取 `system.articlesSortMode`、`system.lettersSortMode`，支持 `random` 随机打乱和 `sequence` 按入库顺序倒序展示，默认均为 `random`。列表首次进入时确定当前顺序（无可用缓存时请求并排序）；真正经历 `App.onHide` 后再次回到前台、用户主动下拉刷新时重新取数并重新排序；从详情或其他页面返回、Tab 切换、分享返回、点赞、收藏、留言不会改变现有顺序，触底分页只追加数据。

列表刷新与 `App.onShow` 的 `dataScopeId` 检查是两件事。分享可能触发微信生命周期，但分享回流会被识别，不触发列表刷新。用户主动下拉刷新仍会强制拉取启动配置和业务数据。

`app.json` 已启用 `lazyCodeLoading: "requiredComponents"`；除非微信平台能力要求调整，不要删除该配置。

## 加载与广告

- 页面级加载统一使用 `components/loading-state`，通用文案为“正在加载”；按钮提交、解锁等即时操作保留各自的紧凑加载反馈。
- 原生模板广告由微信异步填充，不阻塞正文；广告加载失败时通过状态类移除广告槽，避免继续占用列表间距。广告槽的外部间距由父级布局统一控制。

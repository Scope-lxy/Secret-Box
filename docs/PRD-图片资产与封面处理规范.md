# 图片资产与封面处理规范

核对日期：2026-09-12。依据当前图片策略、预览和分享源码核对；实际 COS 配置与真机网络行为仍需另行验收。

## 1. 文档定位

本文是「轻读手记」图片资产、封面底图、COS 派生图、前端展示与失败回退的**唯一技术规格真源**。后台 PRD、小程序 PRD、导入说明和实现文档只描述各自的业务入口与用户可见行为，不重复像素、质量、裁切或回退顺序。

调整图片规格时，必须先更新本文，再同步实现和测试；不得只改某一个页面、上传入口或 COS key 规则。

本文不定义页面视觉样式。文章大卡 `2.35:1`、图册卡片 `3:4` 等是前端容器比例，不是上传或派生图的文件比例。

## 2. 术语与原则

| 名称 | 含义 |
|---|---|
| 原图（`original`） | 上传或抓取后留存的源文件，保留原格式、分辨率和构图。 |
| 中图（`medium`） | 面向大卡、图册首页卡片和正常查看的派生图。 |
| 小图（`thumb`） | 面向列表、常规卡片和打开记录的派生图。 |
| 处理标记（`processingProfile`） | 说明原图应采用哪套派生规则，是素材复用和历史兼容的必要条件。 |
| 普通展示图 | 文章封面、图册、普通静态文章正文图等使用的完整构图图片。 |
| 通用封面底图 | 无图公开内容及手记分享可使用的 `5:4` 分享底图。 |

- 原图始终保留；派生图只用于分发，不替代原图。
- 生成派生图时只缩小、不在存储链路放大。源图过小时，派生图可小于目标边长。
- 普通图的中图和小图必须保持同一完整构图；不得出现中图长方形、小图正方形等不一致结果。
- 图片与页面容器比例不同，由前端负责居中等比填充和视觉裁切；不得为了某个卡片比例破坏普通素材的文件构图。
- COS / 数据万象在上传时持久化生成派生图，是正式处理链路，不是临时 CDN 样式补充。

## 3. 派生图规格

### 3.1 普通展示图：`display-v1`

适用于普通素材、手动上传的文章封面、图册和普通静态文章正文图。

| 版本 | COS 处理语法 | 结果 |
|---|---|---|
| `original` | 不处理 | 保留原文件、原格式和完整构图。 |
| `medium` | `imageMogr2/thumbnail/1280x1280>/format/jpg/quality/82` | 最大边不超过 1280px；仅缩小、不裁切、不放大。 |
| `thumb` | `imageMogr2/thumbnail/480x480>/format/jpg/quality/72` | 最大边不超过 480px；仅缩小、不裁切、不放大。 |

`1280x1280>` 和 `480x480>` 都是最长边约束，不是固定宽高。两种版本展示的是同一张完整图片，只是尺寸和质量不同。

### 3.2 通用封面底图：`share-background-v2`

仅适用于后台配置的通用封面底图。

| 版本 | COS 处理语法 | 结果 |
|---|---|---|
| `original` | 不处理 | 保留原文件，供历史兼容和故障兜底。 |
| `medium` | `imageMogr2/rcrop/500x400/format/jpg/quality/82` | 居中裁切为 `500 x 400` 的 `5:4` JPEG。 |
| `thumb` | `imageMogr2/rcrop/250x200/format/jpg/quality/72` | 与中图使用同一居中 `5:4` 构图的 JPEG。 |

此规则是普通图的明确例外。底图源图不足目标尺寸时，不在 COS 中放大；其显示或分享时可以等比放大，但不会因此提高真实清晰度。

### 3.3 仅保留原图：`original-only`

仅用于公众号文章抓取的以下正文图片：

- GIF 或其他动画图片，避免转为 JPEG 后丢失动画；
- 高度超过宽度 3 倍的长图，避免缩小后文字不可读。

这两类图片不强制生成普通展示派生图，正文按完整图片展示。文章封面不适用 `original-only`，仍使用 `display-v1`。

## 4. 上传、处理与复用

### 4.1 处理链路

普通本地图片（含图册和手工文章封面）由浏览器直传 COS：服务端生成限时签名和对象 key，浏览器上传原图，COS / 数据万象生成与 `processingProfile` 对应的派生图，服务端确认对象可读后登记素材元数据。浏览器不为文章封面做 Canvas 裁切或 JPEG 转码。

公众号文章抓取由服务端校验来源地址、受控下载后转存 COS；普通静态正文图和封面使用 `display-v1`，动画和超长正文图使用 `original-only`。派生图对象可读后才可登记为可用版本，避免前端拿到尚未生成的地址。

单图上传大小上限为 `5MB`。服务端保存原始文件名、尺寸、大小、原图/中图/小图地址、处理状态、失败原因和 `processingProfile` 等元数据；内容保存时校验引用的图片素材存在。

### 4.2 素材复用边界

- 批量上传、导入预检和文章抓取复用，必须同时匹配原始文件的 SHA-256 与 `processingProfile`。
- SHA-256 相同但处理标记不同，不能复用已有派生图；例如，`share-background-v2` 的 `5:4` 裁切底图不能复用为图册或文章普通图。
- 同批相同文件也遵守“哈希 + 处理标记”规则，可以共享同一套正确的素材版本。
- 后台当前的单张上传不会计算 SHA-256，因此不承诺单张上传的跨历史去重或复用。

## 5. 前端展示与适配

### 5.1 版本选择

| 位置 | 正常优先版本 | 展示要求 |
|---|---|---|
| 文章列表常规卡片、详情页推荐常规卡片 | `thumb` | 固定容器内居中等比填充。 |
| 文章列表大图卡片、详情页推荐大图卡片 | `medium` | 固定容器内居中等比填充。 |
| 文章打开记录 | `thumb` | 不为记录列表提前请求原图。 |
| 首页手记图册卡片 | `medium` | 固定容器内居中等比填充。 |
| “我的”及打开记录中的图册缩略图 | `thumb` | 固定容器内居中等比填充。 |
| 图册点击后的图片预览 | `medium` | 优先完整查看画面。 |
| 文章正文 | 对应可用正文图片 | 宽度适配正文，不按封面容器裁切。 |

卡片容器使用居中等比填充（`aspectFill`）实现视觉裁切；文章正文与图片查看使用完整画面，不应因封面比例裁切。源图比例异常时，页面布局不得被图片撑坏。

### 5.2 图册查看与网络故障

用户每次从首页图册、“我的”或打开记录进入图片预览时，都重新尝试同图的 `medium`，即使卡片此前已降级为小图。预览失败顺序固定为：

```text
medium -> thumb -> original
```

预览使用微信原生 `wx.previewImage`，保留原生缩放、左右滑动和长按菜单，不增加自定义全屏页或原图入口。先确认用户点中的图片：正常优先请求中图；中图不可用时按 `medium -> thumb -> original` 降级，首张可用即打开，不得等待整组。传给原生预览的图片列表保持原顺序，其余图片优先使用中图地址，由微信按需加载；原生预览打开后不能替换其 `urls`，其余图片发生网络故障时由原生界面处理，再次从卡片点中该图片时重新执行版本降级。点中图有单图超时和重复点击保护；打开后仅静默预取前后相邻图片的中图或小图，不因预取下载原图。点中图所有版本均不可用时，提示暂时无法查看。原生长按保存的是当前预览版本，不承诺保存原图。
首页图册卡片的“保存原图”属于用户主动操作：点击后先弹出确认提示，确认后按图册顺序逐张优先请求 `original`，缺失时按 `medium -> thumb` 回退，并调用微信相册保存能力；单张下载或保存失败不阻断剩余图片，最后提示已保存数量。该流程不属于普通预加载或原生预览默认加载链路。

首页图册大卡片在首张图片可用前只显示同一中性加载占位；候选版本必须先确认可用后才一次性显示，禁止在可见卡片内依次替换中图、小图或原图。切换图片时沿用同一规则，当前图优先，相邻图在后台有界预加载。

普通卡片优先请求表中指定版本。出现网络或对象异常时，可以尝试同图的其他可用版本；列表和常规卡片不得将原图作为常规预加载资源。

## 6. 分享封面

### 6.1 合成方式

分享卡片由小程序本地画布合成，按 `750 x 600` 设计坐标排版，导出为 `500 x 400`、质量 `0.8` 的 JPEG。服务端与云服务器不生成分享 PNG，只提供可访问的图片来源和分享配置。

来源图片填充 `5:4` 分享画布时，使用居中等比填充（`aspectFill`），不拉伸。小尺寸来源可以在画布上被放大，但不会变得更清晰。

### 6.2 来源优先级

| 分享内容 | 首选底图 | 无内容图片时 |
|---|---|---|
| 文章 | 文章自身的 `coverImage`；绝不使用正文配图 | 通用封面底图；未配置时内置底图。 |
| 心笺 | 通用封面底图（当前仅文案形态，无内容图片） | 未配置时内置底图。 |
| 手记文案、音频 | 通用封面底图 | 未配置时内置底图。 |
| 手记图册 | 当前图册第一张图片 | 图册无图片或来源失败时通用封面底图；未配置时内置底图。 |

文章和心笺都复用“文案”类型的日期、封面文案、遮罩和内置排版机制；公开内容的标题来自内容自身，不使用手记标题库。文章无封面时使用与文章列表展示一致的稳定通用底图选择（同一 `contentId`）。当前心笺只有文案形态，因此始终从通用封面底图开始。手记图册使用当前图册第一张图片，并复用图片版本降级规则。通用封面底图一经上传并启用，即优先于内置底图。

### 6.3 分享失败回退

有内容图片时，先尝试同一来源图片的可用版本；来源无法使用时，回退到通用封面底图；通用底图也不可用或未配置时，才回退内置底图。无图公开内容和无图册图片都从通用封面底图开始。所有回退必须终止，禁止无限重试。

## 7. 历史素材兼容

- 历史文章封面和通用封面底图缺少 `processingProfile` 时，优先使用仍留存的原图，避免继续使用历史的错误正方形或不匹配裁切派生图。
- 不批量重写历史 COS 对象；新上传、重新处理或明确迁移时才按本文生成正确规格。
- 原图已丢失的历史错误裁切无法恢复原始构图，应以当前可用版本降级展示并保留可追溯元数据。

改动后至少核对：普通图的中小图构图一致；通用底图中小图都是同一 `5:4` 居中裁切；文章分享只取 `coverImage`；手记图册分享优先取图册第一张图片；当前无图心笺和无图册优先通用底图；图册预览可在中图失败后退回小图/原图，下一次打开仍会重试中图。

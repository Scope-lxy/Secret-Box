## 2. 当前视觉基线

以下参数直接来自当前小程序样式，不再沿用旧原型的 16px 卡片内边距和 72px 邮戳尺寸。

| 项目 | 当前值 / 规则 |
|---|---|
| 页面外边距、普通卡片间距 | `24rpx`（375px 设备宽度下约 12px） |
| 普通卡片内边距 | 水平、垂直均为 `20rpx`，特殊卡片按页面样式覆盖 |
| 卡片圆角 | `16rpx` |
| 页面 / 卡片背景 | `#f6efe6` / `#fffaf2` |
| 正文 / 次级文字 | `#493829` / `#8b7461` |
| 主强调色 | `#d49a68`，深色 `#a66b42` |
| 正文字号 | 普通 / 较大 / 最大 `32/36/40rpx` |
| 手记打开前提示语 | `36/40/44rpx`，行高 `1.6`，左缩进 `8rpx` |
| 标签至引导文案间距 | `20rpx`；引导区至按钮间距由 `gap: 20rpx` 控制 |
| 邮戳 | 独立 SVG，宽 `216rpx`，定位及旋转由首页 WXSS 控制 |
| 图册展示容器 | `3:4`，图片文件构图保持规则见图片规范 |
| 文章正文 / 媒体间距 | 普通/较大/最大分别 `20/24/28rpx` 与 `24/28/32rpx` |
| 底部安全区 | Tab 与记录列表分别使用现有安全区样式，不写死设备高度 |

字号为共享 Token 与组件变体共同管理；完整列表见 `tokens.wxss`。改动主色、层级、间距或卡片结构时，应同步本文和相应页面验收项。

## 4. 关键交互

| 交互 | 当前实现与边界 |
|---|---|
| Tab 切换 | 首页、文章、心笺、我的固定顺序，自定义 TabBar 支持前三项隐藏；启动超时降级强制隐藏首页 |
| 打开与换一个 | 卡片内完成；共用当前账号、数据范围、自然日打开上限，默认 5，0 不限，没有单独每天 2 次换取规则 |
| 内容抽取 | 随机打开排除近 30 天已打开内容；指定有效分享内容不受随机排除限制，但仍校验存在性、启用状态和当日上限 |
| 引导文案 | 独立文案包下发，按首个中文逗号分行，空值或异常整体回退当前两条默认文案池 |
| 打卡 | 服务端记录日期、排名和奖励，卡片内展示两行 14 天日历；前端按返回值更新统计 |
| 文章 | 三种列表布局、预览与当天全文解锁；每篇文章独立推荐，从全内容池随机选取最多 200 条继续阅读、每次 20 条；六个广告配置项按当前实例生效 |
| 留言 | 配置明确开启才展示；服务端先拦截词检查，再按文本审核配置执行远程审核；图片审核尚未实现 |
| 激励广告 | 完整观看信号来自客户端微信回调；不可用时按广告位配置放行，服务端没有独立完成凭证核验 |
| 插屏广告 | 支持首次延迟和循环间隔；展示前等待连续空闲，忙碌、分享、预览等状态暂停调度 |
| 点赞、收藏、分享 | 按各内容类型展示计数；分享记录表示调起面板，不表示已送达 |
| 图片预览 | 点击图先验证 `medium → thumb → original`，首张可用即调用 `wx.previewImage`，保留原生查看能力 |
| 注销 | 设置页显示实例开发者邮箱，用户申请后由管理员核实并手动处理，不提供定时自助注销 |

## 5. 样式实现边界

开发复用当前小程序组件与样式参数，具体数值见 `miniprogram/styles/tokens.wxss`、`styles/components.wxss` 及页面 WXSS；上述路径均相对仓库根目录。

当前实现分工：

| 模块 | 现有实现 |
|---|---|
| 手记、打卡与音频大卡 | `pages/home/home.*`，不是独立 `DailyContentCard` / `CheckinCard` 组件 |
| 文章卡片与阅读详情 | `pages/articles/`、`pages/article/`，共享文章工具与样式 |
| 操作条、内容卡片与记录列表 | `styles/components.wxss` 及各页面 WXML |
| 页面加载与沉浸式导航 | `components/loading-state/`、`components/immersive-nav/` |
| 展开收起 | `components/expandable-text/` |
| 原生广告 | 页面 `<ad>` 与 `utils/native-ad.js`、`utils/list-ads.js` |
| 图册查看 | `utils/image-preview.js` 调用 `wx.previewImage` |
| 留言引用卡 | `message-reference-text`、`message-reference-article`、`message-reference-audio`、`message-reference-album` 四个现有组件 |

“我的”及二级记录列表适配规则：

- 范围包括最近打开、累计打开、互动记录、我的收藏、我的留言及其引用卡；以“较大”档为基准适配普通和最大，文章页与心笺页保持现有排版。
- 正常记录的文章标题、音频标题和文字摘要共用 `--type-body`、`--color-text-secondary`、`400` 字重及相同字距；引用文字、文章标题和音频标题统一使用 `calc(var(--type-body) - 2rpx)`，三档分别为 `30rpx / 34rpx / 38rpx`。
- 正常记录与引用文章标题共用行高，普通 `1.7`、较大 `1.5`、最大 `1.35`，不另设引用文章行高。普通档位适当增大行距，让两行标题与封面高度更接近。正常记录及引用音频标题行高为普通/较大 `1.5`、最大 `1.4`，正文摘要仍使用现有内容行高。
- 正常文章封面固定 `112rpx` 正方形，引用封面固定 `104rpx` 正方形，标题顶部对齐；音频播放按钮固定 `80rpx`，图册缩略图按容器宽度约展示 4.5 张，不为三档字号另设图片或按钮尺寸。
- 正常列表及引用音频的左侧内容自然撑满播放按钮所在行，进度条底边与按钮底边对齐，不按字号硬编码高度。
- 四种引用卡统一浅色背景、内边距、圆角和左侧细边；文字引用由外壳包住，内层负责最多两行省略，不显示展开按钮。不得通过固定高度、整体 `scale` / `zoom` 或运行时高度测量实现缩小。
- 累计打开、互动记录、我的收藏、我的留言统一底部留白和安全区，背景覆盖至安全区底部。`expandable-text` 隐藏全文测量内容的溢出在共享组件内处理，不得扩大页面滚动范围、露出白底或增加无内容滚动；保留展开/收起，不添加单页固定高度补丁。

间距规则：

- 组件内部优先使用父容器 `gap`。
- `padding` 只负责内容与容器边缘的安全距离。
- 不用多个子元素 `margin` 叠加凑间距。

## 6. 必须保留的产品状态

首页：

- 手记未打开。
- 手记 loading。
- 手记结果。
- 图册结果。
- 当日手记打开次数达到上限。
- 留言输入展开。
- 打卡未完成。
- 打卡 loading。
- 打卡成功态。
- 广告失败轻提示。

内容流：

- 文章列表三种布局与无封面收敛状态。
- 文章详情未解锁预览、激励处理中、当天已解锁全文、每篇文章分别随机且每次 20 条分页的继续阅读和六个独立配置项对应的广告链路；继续阅读从全内容池随机选取最多 200 条，加载完本轮内容后自然结束且不循环，同一篇文章的推荐在 30 分钟窗口内供所有用户复用，续页沿用旧种子，推荐广告按累计列表位置延续；正文中段广告仅在长度和段落边界条件满足时插入。
- 心笺列表。
- 原生广告位。
- 点赞已选中/未选中。
- 收藏已选中/未选中。
- 留言输入。
- 我的留言正文默认折叠两行并支持展开/收起；引用卡通过四个专用组件渲染，手记/心笺文字与文章标题最多两行省略且不展开，图册显示横向缩略图条，音频显示播放器。文字引用必须完整置于统一浅底外壳内，三档字号均不露出第三行或裁切第二行。
- 空状态。

我的与设置：

- 我的统计入口。
- 历史记录列表。
- 互动记录覆盖手记文案、音频、图册、心笺和文章；三类手记分别展示正文、播放器、图册缩略图条。已打开手记的分享记录到当前内容，首页未打开内容的类型轮换分享不写入互动记录。
- 互动记录左上角只显示“点赞过”“分享过”“留言过”等互动标签，沿用内容类型标签样式；同一内容的多个互动标签同排展示。
- 互动记录、累计打开、我的留言和我的收藏的列表时间只显示时间信息，不追加动作词。
- 收藏列表。
- 留言列表。
- 设置列表。
- 通过微信官方选择头像、填写昵称和手机号授权能力更新资料。
- 手动输入后保存。
- 注销申请方式提示和开发者邮箱。

## 7. 开发验收方式

建议验收分 4 轮：

1. 页面还原验收：逐页对照当前页面源码、本文及小程序 PRD，检查视觉、间距、层级、状态；“我的”及二级记录列表按小程序端 PRD 当前规范，分别在普通、较大、最大档位检查文章标题与封面顶部关系、音频进度条与播放按钮底边对齐、引用卡完整外壳及两行省略效果；二级列表滚动到底部后检查背景、留白和安全区，展开/收起及切换字号后不得由隐藏测量内容产生额外滚动。
2. 主流程验收：打开手记、换一篇、打卡、收藏、点赞、分享；留言功能开启时再验收留言。
3. 配置验收：后台关闭广告、隐藏 Tab、切换文案和留言功能后，前台正确变化；首页隐藏时重新加载直接进入首个可见 Tab；文章三种布局、五档展开位置、详情 `contentId` 路由、预览/解锁状态和六个广告配置项按当前小程序统一生效；文章列表翻页后原生广告位置按全局序号延续，详情正文中段广告只在服务端分段条件满足时出现；留言关闭时“我的”页隐藏“我的留言”，剩余三项统计卡三列等宽铺满；切换用户数据模式后，按小程序端 PRD 验收前台范围刷新、旧范围写入拒绝和手动重试。
4. 合规验收：微信官方隐私授权、手机号授权、内容安全、注销申请与 Admin 手动处理。

P0 不允许遗漏：

- 首页默认落地。
- 首页隐藏时冷启动不显示首页业务内容，直接进入文章、心笺、我的中的首个可见 Tab。
- 手记和打卡在首页卡片内完成。
- 文章列表、详情 `contentId` 路由、Markdown 清洗后的预览、当天解锁、继续阅读和广告位完整可用；未解锁详情不得下发或展示完整正文，解锁后正文图片、媒体边界和可选中段广告间距稳定。
- 留言功能开启时留言仅用户与运营可见且提交前经过服务端检测；关闭、配置缺失或请求失败时所有留言入口和内容隐藏。Admin 保留远程启停能力，实际实例配置不由源码核验推断。
- 首页分享在当前启用类型中按文案、音频、图册顺序轮换；已打开手记分享绑定当前内容。两类链接、静默检查、异常后的“随机打开”选择及计次规则以《PRD-轻读手记小程序端》的“4.1.1 打开手记流程”为唯一标准。
- 普通图片列表和预加载不加载原图；用户主动保存原图及规定的失败回退链路除外。
- 设置页顶部第一个分区为个人资料。
- 页面视觉与共享样式参数一致，修改设计先更新本目录规范。

## 8. 核验边界与维护

- 次数、内容抽取、账号与数据范围、留言检查由当前服务端实现决定；客户端广告完成回调的限制单独保留，不能写成服务端可独立验证观看。
- 本文是按源码修订的设计规范；真机字号、媒体加载、广告库存、授权与分享效果仍须在实际环境验收，不把单元测试通过写成上线完成。
- 未接入的图片审核、订阅发送和自助注销等边界见[已知暂缓事项](已知暂缓事项.md)。
- 原有产品 PRD 的字段、流程与验收条目继续在本目录维护；目录整理不得删除有效需求或用一句“以实现为准”替代需求细节。

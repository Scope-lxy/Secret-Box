# 轻读手记后台 PRD

版本：v1.4（2026-09-12 实现核对）
来源：历史后台需求和设计规范已汇总进本文档，旧散文档不再单独保留。
适用范围：Web 管理后台、服务端管理能力；按本地正式源码核对，不代表线上配置或微信平台状态
核心架构：同一套后台管理多个小程序，采用“全局内容池 + 全局分享模板池 + 小程序实例配置”。

三层职责：

| 层级 | 唯一职责 | 不负责 |
|---|---|---|
| 微信公众平台 | 签发 `AppID / AppSecret`，创建广告单元，配置隐私保护指引与合法域名，接收代码审核并发布 | 不管理日常内容和页面业务配置 |
| Admin 后台 | 保存每个 AppID 对应的内容池、功能、页面文案和广告位绑定，并为服务端调用微信接口保存 `AppSecret` | 不表示或推测微信的审核、发布、隐私配置状态 |
| 小程序实例 | 运行同一套前端代码，并按自己的运行时 AppID 获取对应的 Admin 配置 | 不在源码中手工绑定 Admin 内部 ID |

微信公众平台与 Admin 是两个独立后台。微信公众平台是平台配置和发布状态的正式真源；Admin 是业务内容和功能配置的正式真源。

## 1. 后台目标

第一版后台用于统一管理「轻读手记」及后续同类小程序实例。后台需要同时支持共享内容资产、按小程序独立配置广告、文案和系统字段，并避免运营在多小程序场景下误操作。

核心原则：

- 多个小程序共用同一套后台和同一套前端源码。
- 小程序运行时通过微信官方 `wx.getAccountInfoSync()` 取得自己的 AppID，服务端按 AppID 自动匹配 Admin 实例。
- Admin 内部 ID 仅作为数据库稳定主键，不在运营界面展示，也不要求写入小程序源码。
- 内容池只保存内容资产，不保存广告、分享、文案和系统配置。
- 分享模板池是全局共享资产，不属于内容池，也不按小程序分组。
- 每个小程序实例只保存当前绑定的内容池，以及自己的广告、文案、上限和系统字段。
- 操作界面保持单层、直接、低学习成本。

## 2. 后台信息架构

一级菜单：

| 分组 | 菜单 | 用途 |
|---|---|---|
| 概览 | 数据概览 | 查看全部小程序和当前小程序运营数据 |
| 共享内容与素材 | 内容管理 | 管理内容池、普通内容桶和文章 |
| 共享内容与素材 | 导入内容 | 统一导入私密文案、私密音频、私密图册、文章和心笺，并在确认前预览 |
| 共享内容与素材 | 分享模板 | 管理所有小程序共用的手记分享模板 |
| 共享内容与素材 | 图片素材 | 管理全局图片素材与 COS 配置 |
| 全局运营 | 留言管理 | 查看、搜索、筛选、删除用户留言 |
| 全局运营 | 内容安全 | 管理全局内容安全策略与拦截词 |
| 小程序 | 小程序管理 | 接入、永久删除和选择业务实例 |
| 小程序 | 小程序配置 | 管理当前小程序的身份信息、内容池绑定和前台规则 |
| 小程序 | 广告设置 | 管理当前小程序的广告位和广告单元 |
| 后台设置 | 管理员账号 | 管理后台共享登录账号和密码 |

规则：

- 左侧菜单保持单层；分割线仅用于区分共享资产、全局运营、小程序和后台设置，不提供二级菜单。
- 操作日志不作为独立一级菜单，放在数据概览的“最近操作记录”区域。
- 左侧菜单栏底部固定展示“当前配置小程序”切换器。
- 仅当前小程序配置和广告设置展示当前小程序；共享资产和全局运营页面不展示小程序上下文。

## 3. 当前小程序上下文

后台必须区分“全局内容池”与“当前小程序配置”。

| 模块 | 是否跟随当前小程序切换 | 说明 |
|---|---|---|
| 内容设置/内容池管理 | 默认跟随当前小程序绑定内容池 | 内容池本身是全局内容资产 |
| 分享设置 | 否 | 编辑所有小程序共用的分享模板池 |
| 广告设置 | 是 | 按小程序保存广告位 |
| 小程序配置 | 是 | 当前小程序基础配置、内容池绑定和前台规则 |
| 图片素材 | 否 | 全部内容池共用的图片素材与 COS 配置 |
| 内容安全 | 否 | 所有小程序共用的安全策略与拦截词 |
| 留言管理 | 支持筛选 | 可按来源和小程序筛选 |
| 小程序管理 | 否 | 管理全部已接入的小程序 |
| 管理员账号 | 否 | 后台共享登录账号和密码 |

切换规则：

- 顶部或侧边栏下拉选中目标小程序。
- 当前小程序配置和广告设置立即刷新为该小程序的配置。
- 不跨小程序混用按钮文案、广告 `adUnitId`、打开上限和系统字段。
- 小程序只通过 `contentPoolId` 调用内容池；分享模板统一读取全局 `shareSettings`。

## 4. 小程序管理

小程序添加到 Admin 后即视为“已接入我们的服务”。Admin 不设置“待审核”“待发布”“已发布”等状态，因为普通 `AppID + AppSecret` 模式无法可靠读取微信审核状态，人工状态也会与微信公众平台产生双重真源。审核与发布结果只在微信公众平台查看。

Admin 提供“永久删除”这一业务动作，不保留停用或归档状态。删除后该 AppID 无法继续访问我们的服务，并从 Admin 小程序切换器和已接入列表移除。

### 4.1 新增小程序

字段：

| 字段 | 必填 | 说明 |
|---|---|---|
| 小程序名称 | 是 | 默认正式名称为「轻读手记」；后台可为不同实例设置识别名称 |
| `AppID` | 是 | 微信小程序 AppID |
| `AppSecret` | 是 | 仅服务端保存 |
| 开发者邮箱 | 是 | 用于用户申请查阅、更正、删除信息或注销账号 |
| 备注 | 否 | 运营备注 |
| 内容池 | 是 | 默认绑定主内容池 |
| 用户数据模式 | 是 | `共享数据`或`独立数据`，默认`共享数据` |

创建后系统自动：

- 生成该小程序的广告配置。
- 生成该小程序的文案配置。
- 生成该小程序的系统配置。
- 默认绑定主内容池。
- 默认使用`共享数据`模式。

初始化规则：

- 默认绑定主内容池，不复制内容。
- 用户数据默认与绑定同一内容池、且同样使用`共享数据`模式的小程序共享。
- 广告设置、文案设置、打开上限和系统设置从系统默认值初始化。
- 新增完成后无需修改小程序源码中的实例 ID；同一份代码会按运行时 AppID 自动读取本实例配置。

### 4.2 永久删除小程序

第一版直接永久删除小程序实例，不保留已停用副本。

规则：

- 必须二次确认，并明确该操作不可撤销，删除后该 AppID 将无法访问我们的服务。
- 系统必须至少保留一个已接入小程序；只剩一个时不允许删除。
- 删除小程序实例配置、登录会话、代码上传密钥与上传记录，以及当前实例独占的用户和业务数据；上传配置清理失败时，实例删除结果不回滚，后台必须明确提示人工检查。
- 共享内容池、共享文案、共享图片，以及仍被其他小程序或账号持有的数据必须保留。
- 不影响其他小程序及其仍持有的数据。

### 4.3 编辑小程序

- 在小程序管理中点击“编辑配置”后，系统选中该小程序并打开“小程序配置”。
- “小程序配置”的第一项为基础信息与内容池，用于修改名称、`AppID`、`AppSecret`、备注和内容池绑定。
- 系统模式配置区在现有“默认模式 / 审核模式”下拉框旁增加“共享数据 / 独立数据”下拉框，并由“保存模式配置”统一保存；不增加需要运营理解或手动维护的“用户空间”配置。切换说明必须明确提示：服务端已有数据会自动合并，但用户设备中属于旧范围、尚未同步的离线留言、删除和互动可能在范围刷新时作废。
- 广告设置作为当前小程序的独立页面继续编辑。

### 4.4 小程序分组

- 每个实例属于一个分组或未分组；默认未分组。列表分组列位于备注后，按钮只显示“改”。点击后用项目统一弹窗选择分组并保存。
- “设置分组”用统一弹窗新增、改名、删除分组；支持直接输入新名称后保存，取消不保存草稿。名称不能为空、不能重复，最多 30 字、50 个分组。
- 改名保留实例归属；删除只解除归属，不删除实例或业务数据。服务端原子处理分组定义和归属，不能用过期页面的完整实例列表覆盖其他配置。
- 保存后立即同步列表、指派弹窗和状态面板筛选项，无需刷新页面；失败保留草稿并显示原因。其他窗口修改分组后，旧弹窗保存须提示重新打开。

## 5. 数据概览

### 5.1 统计卡片

“当前小程序数据”和“所有小程序数据”均为以下 8 项，固定每行 4 项、共 2 行，不新增“新增用户”。维持桌面布局和现有卡片宽度；卡片高度容纳标题及分组筛选，右侧服务配置检查与两张卡片整体对齐。

| 指标 | 说明 |
|---|---|
| 总用户数 | 所选实例关联的账号总数；已关联为同一账号的跨实例用户只计一次，不依赖近期日志数量 |
| 周活用户 | 今日及前 6 天有有效访问记录的去重用户，不累加每天的人数 |
| 今日访问人数 | 今日有有效访问记录的去重用户 |
| 今日访问人次 | 登录复核及已登录首页访问记录；每个实例内同一用户 60 秒内的多个请求合并一次 |
| 成功打卡 | 今日成功打卡次数；失败与同一请求重试不增加 |
| 打开手记 | 今日成功打开手记次数；新的成功操作继续计次，同一请求重试不增加 |
| 打开文章 | 今日成功提供全文次数；每个实例内，同一用户、同一文章、同一天只计一次，预览不计 |
| 新增留言 | 今日成功提交留言数，不含审核拦截或失败请求 |

- 所有日期统一按北京时间计算。最后四项也是今日数据，只在标签中省略“今日”。
- 访问数据由后台复用现有登录复核和已登录首页请求，统一去重；小程序保留已有会话时的回前台复核，不为统计增加独立请求或触发首次登录。“访问人次”不是严格的前后台切换次数。
- 客户端与服务端需保持当前数据范围与接口契约一致。首次只浏览、未触发登录的访问尚不计入账号访问数据；过去未记录的行为无法追补。
- 共享账号按账号身份去重；无法关联身份的不同账号不能推断为同一自然人。共享数据模式不共享运营次数，次数按实际访问的实例累计。
- 文章全文统计合并历史解锁记录与新成功记录，并排除数据模式迁移产生的副本。历史未记录的直接全文展示、跨实例共享全文读取无法追补。
- 指标悬停提示显示口径；统计读取失败显示“--”，不能把上次分组的数值显示在新分组下。

### 5.2 分组与 15 日趋势

- “所有小程序数据”右上角使用紧凑原生下拉框，默认“全部”，可选择已保存分组；仅聚合所选范围内现役实例。
- 空分组 8 项和趋势均为零；删除当前筛选分组后回到“全部”。“当前小程序数据”不受分组筛选影响。
- 15 日趋势包含今天及前 14 天，系列顺序为“访问人次、访问人数、成功打卡、打开手记、打开文章”，范围与“所有小程序数据”的当前分组一致。
- 快速切换分组时仅应用最新响应，迟到的设置或概览响应不得覆盖新的分组选择。

## 6. 内容设置

内容设置按内容池管理。

### 6.1 内容池管理

内容池能力：

- 新增。
- 编辑。
- 删除。
- 查询。
- 查看被多少小程序绑定。

删除规则：

- 必须二次确认。
- 若内容池正在被小程序使用，不允许删除。
- 删除内容池时，池内所有内容一并删除。
- 后台删除接口必须同时删除内容池配置和内容池数据，不能只删除列表记录。

切换规则：

- 通过下拉选择或点击表格行切换当前编辑内容池。
- 页面顶部展示当前内容池名称。

### 6.2 内容桶

每个内容池内部包含 5 个内容桶：

| 内容桶 | 说明 |
|---|---|
| 私密文案 | 小程序前台“手记”内容 |
| 私密音频 | 小程序前台“音频”内容 |
| 私密图册 | 小程序前台“图册”内容 |
| 心笺文案 | 心笺列表内容 |
| 文章 | 文章列表和长文详情内容 |

每个内容桶都支持：

- 增删改查。
- 单条新增。
- 批量导入。
- 数量统计。

操作入口规则：

- 单条新增、编辑、删除放在对应内容卡片内部；表格操作列提供单条“保存”，每张内容卡片同时提供“保存全部”。
- 每个内容卡片右上角只放一个单条新增入口。
- “导入内容”类型切换顺序固定为“私密文案 → 私密音频 → 私密图册 → 文章 → 心笺文案”。文章在内容管理页使用独立“文章管理”区域，但批量导入进入同一“导入内容”页面并预选文章。
- 每个内容卡片右上角保留“批量导入”入口；点击后进入独立的“导入内容”页面并预选类型。
- 批量导入成功或失败只在当前导入页提示结果，不自动切换到内容管理或刷新列表；普通内容重新选择下一批来源即可继续，公众号文章发布成功后清空当前链接和预览并留在文章导入面板。
- 侧栏“导入内容”可直接进入同一页面；类型切换、来源选择、预览和确认统一在此页完成。
- 导入确认前必须先解析、匹配并展示预览，不直接覆盖内容池。
- 重新选择文件或文件夹时替换当前整批预览，不追加旧内容。
- 导入中的类型切换、来源选择和预览编辑必须锁定；图片失败时允许单独重试或移除异常图片。

### 6.3 批量导入字段

| 内容类型 | 导入来源 | 必填内容 | 规则 |
|---|---|---|---|
| 私密文案 | 一份 TXT | 文案 | 用空行、序号或 `---` 分隔多条文案 |
| 私密音频 | 多个音频文件 | 音频 | 每个文件生成一条私密音频 |
| 私密图册 | 一个图片文件夹 | 图片 | 可识别不同子目录内的图片，或用相同名称加序号作为分组标识，例如 春日01.jpg、春日02.jpg。每组 1-9 张。 |
| 心笺文案 | 一份 TXT | 内容 | 用空行、序号或 `---` 分隔多条内容 |
| 文章 | 每行一个公众号 URL | 标题、正文 | 首版只接受 `mp.weixin.qq.com`，异步抓取后预览并确认发布 |

私密图册规则：

- 图片不使用 Excel、粘贴表格或 ZIP 导入。
- 可识别不同子目录内的图片，或用相同名称加序号作为分组标识，例如 春日01.jpg、春日02.jpg。每组 1-9 张。
- 未分组的单张图片各自成为一个图片组。
- 每组保留前 1 到 9 张图片；超过上限时按文件名排序截断，不标记为导入异常。

私密音频规则：

- 支持 MP3、M4A；单文件上限 50MB。
- 批量选择多个音频文件，每个文件独立成为一条私密音频；默认标题为原始文件名移除最后一个扩展名后的内容，运营可在内容管理中单独修改标题。
- 浏览器在选择文件时读取原始文件名。COS 对象 key 由服务端随机生成，避免重名冲突和路径风险；保存内容时同时保存标题、原始文件名、大小、MIME 类型、时长（可获取时）与 COS URL。
- 标签仅用于后台分类；小程序播放器显示标题，标题过长时在有限区域内滚动展示。
- 音频不走图片压缩和数据万象图片处理链路。
- 后台运营上传的音频完成上传后即可使用；只有当前小程序已开启“私密音频”时，才会被随机下发。生产环境如接入平台音频安全检测，检测失败的文件应自动隐藏并通知管理员，不设置人工“待审核”状态。
- 手记被打开时，打开记录同时保存 `title`、`originalFilename`、`audioUrl` 和 `durationSeconds`；小程序的「我的」「累计打开」直接使用这些字段播放，不能只保存标题摘要。

#### 后台试听

- 音频内容表增加“试听”列，行内只显示与操作列一致的裸文字“试听”按钮；播放中当前行切换为“暂停”。
- 点击“试听”后，在后台页面右下角显示一个悬浮播放器，不跳转独立播放页，也不使用普通模态弹窗。播放器复用小程序打开音频手记的完整卡片结构与视觉语言，但按后台密度缩小。
- 悬浮播放器显示标题、当前时间、播放状态、剩余时间、总时长、波形刻度、可拖动进度条、播放/暂停和重播（回到 0 秒）控件；不提供循环、音量或下载等高级功能。
- 页面同时只播放一条音频；点击另一条试听会暂停上一条并切换到新音频。切换分页、刷新内容或删除当前音频时，播放器停止并清零，不在页面不可见时继续播放。
- 页面初始不创建音频对象，也不请求音频文件；首次点击试听时才创建单个 `Audio` 实例并设置音频地址，使用 `preload="none"`。试听状态只存在于当前后台页面，不写回内容数据。
- 播放失败、地址缺失或媒体不可用时，播放器在当前位置显示明确的不可播放状态；不影响内容编辑和保存。

文章导入规则：

- “批量导入”每行接收一个公众号文章 URL，提交后立即返回任务 ID；服务端在后台逐条抓取并持久化进度，Admin 轮询任务状态，不占用一个长连接等待整批完成。
- 每次进入文章导入页都从空白链接和空白预览开始，不从浏览器会话恢复旧任务；本轮任务及其移除、编辑状态只在当前打开的导入页面内保留。离开后再次进入视为新一轮导入。
- 每篇自动提取标题、作者、正文、发布时间和封面。作者字段优先使用蓝色的公众号账号名称，页面账号节点与脚本账号字段均无有效值时，才使用灰色的文章作者名称兜底；两者均缺失时须在预览编辑中补充作者后才能确认导入。预览与最终保存使用同一作者字段，运营手动编辑后以编辑值为准。成功项默认保留并进入最终导入范围，不设置复选框或单篇确认步骤；失败项和重复项必须给出原因且不会写入内容池。
- 导入预览区固定为三列等宽布局并铺满卡片可用宽度；各阅读窗口保持接近小程序手机页面的纵横比，标题、正文、元信息、内边距、段落间距和工具按钮随卡片宽度在限定范围内同比缩放，正文图片铺满内容宽度且只能纵向滚动。每张成功卡片右下角由上到下提供圆形删除、编辑按钮，失败和重复卡片至少提供删除按钮。删除不弹二次确认，只从当前批次预览移除，不影响已正式发布内容；轮询期间移除的条目不得被后续结果重新加入。编辑复用文章新增和已发布编辑的 `900px` 双栏弹窗：左侧为两行标题和 Markdown 正文，右侧为封面、发布时间和实时阅读卡片；顶部右侧按“取消｜保存”排列，不设置底部操作栏。保存更新卡片预览并返回，取消不保存；存在未保存修改时关闭需确认放弃。
- 导入预览卡片右上角“确认导入”负责把当前仍保留的全部成功文章一次性写入内容池；全部成功项被移除后按钮不可用。确认完成后，服务端按现有素材引用规则回收被移除文章的无引用 COS 图片；整批放弃则由任务过期清理回收。
- 来源 URL 规范化后计算 SHA-256，用于同批和当前内容池最终去重；确认发布时服务端必须再次去重。
- 文章页面 URL 只允许 `mp.weixin.qq.com`；正文图片允许来自任意公网图片主机，不再依赖微信图片域名白名单。每次请求和跳转都重新校验协议、主机和标准端口；DNS 解析结果必须全部为公网地址，禁止账号信息、内网/回环/链路本地地址、危险端口和超限重定向，防止 SSRF 与 DNS 重绑定。
- 公众号 HTML 和图片分别限制响应体积、MIME 类型和抓取超时；正文只保留允许的富文本标签与属性，移除脚本、样式、事件、协议相对 URL 和其他可执行内容。
- 发布时间优先读取公众号页面的 `article:published_time`、`publish_time`、`create_time`、`ori_create_time`、`ct` 等字段（支持日期文本及 Unix 秒/毫秒时间戳），也读取页面可见发布时间。无法识别有效原始发布时间时，该篇标记为失败且不能确认导入，不使用抓取或导入时刻冒充原始发布时间。
- 正文图片经格式魔数校验后按内容哈希转存项目 COS，正文只保存项目 HTTPS 地址；封面同步登记为图片素材并复用相同哈希素材。抓取失败不得留下半发布文章。
- 同批文章完成抓取后，仅对位于每篇边界、带推广/互动/链接列表信号且至少 3 篇相同的语义块执行“批次重复模板”清理；短文、只有 1–2 篇出现的片段与正文主题重复不得触发。移除内容可在预览中按原始顺序恢复，批次移除的图片只恢复文字。
- URL 导入只是运营工具，不等于获得转载授权。运营必须确认自有版权或已获许可，保留来源 URL 和发布时间，不得用本功能规避公众号访问控制、批量搬运第三方内容或删除依法必须保留的署名与出处。

批量导入通用规则：

- 每批内容最多 200 条；图片准备和完成登记接口每批最多 100 张，客户端按块调用。批量删除每次最多 100 条，当前内容类型至少保留一条；这些限制不意味着初始化时要生成示例内容。

- 标签默认值为“默认”，只供后台分类，小程序端不展示。
- 音频初始标题取原始文件名去掉最后一个扩展名；导入完成后可在内容管理中单独修改标题，标题不影响标签或原始文件名。
- 预览中允许修改普通文本内容和图片组标签；文章新增、已发布编辑和导入草稿编辑复用同一个双栏弹窗。左侧为两行标题和 Markdown 正文，右侧为封面、发布时间和独立滚动的阅读卡片；导入阶段即可修正抓取到的封面和原始发布时间。文章封面选择本地图片后直传 COS，上传成功即自动选中；取消、替换或移除后只回收本次新上传且未被其他内容引用的临时封面。
- 图片支持 JPG、JPEG、PNG、WebP、GIF，单张上限 5MB。
- 音频支持 MP3、M4A，单文件上限 50MB。
- TXT 优先按 UTF-8 读取，并兼容常见旧版中文 TXT 编码。
- “确认导入”仅追加当前预览中的新内容；同一批次因网络中断重试时不得重复追加。

### 6.4 文章管理与展示规则

- 文章管理支持新增、编辑、预览、单篇删除、批量删除、批量导入和发布时间；“新增”和“编辑”在当前页打开统一弹窗，保存成功后关闭弹窗并刷新列表，保存失败保留全部输入。关闭存在未保存修改的弹窗时需确认放弃。批量删除不得删空当前内容池的全部文章。
- 编辑器保存标题、作为正文唯一真源的 `bodyMarkdown`、发布时间、封面素材、来源 URL 和来源哈希；预览 HTML 只按需派生，不并行保存。手工新建文章可不含来源 URL。封面只允许选择本地图片，沿用后台图片直传 COS 流程，成功后自动绑定。
- “文章展示设置”位于“小程序设置”，对当前小程序内全部文章统一生效，但不跨小程序实例共享。切换当前小程序后必须加载和保存该实例自己的配置。
- 列表布局提供常规卡片、大图卡片、混搭模式三项；常规卡片使用左侧固定三行内容区（标题最多两行，底部固定作者与点赞/收藏数据）加右侧固定正方形中心裁切封面，大图卡片使用 `2.35:1` 通栏封面，混搭模式在前两项间稳定均衡分布。
- 展开位置提供最早 `10vh`、较早 `20vh`、适中 `30vh`、较后 `40vh`、最晚 `50vh` 五个固定档位，默认“较早”，不提供自定义高度。展开按钮文案默认“展开全文”。
- 文章广告设置包含文章原生模板广告、文章插屏广告、文章详情激励视频、文章详情插屏广告、文章顶部原生模板广告和文章尾部原生模板广告六个独立广告位；前两项用于文章列表页，后四项用于文章详情页。`adUnitId`、免广告次数、弹窗提醒和无广告放行规则均以当前小程序的广告设置为真源。“小程序设置”只管理文章展开文案、展开位置和列表布局。
- 用户当天解锁记录写入 `article_unlocks`，继续阅读列表从其他文章中随机返回最多 100 篇，按每页 20 篇分页加载；可推荐文章不足 100 篇时自然结束，同一详情页会话内分页顺序稳定且排除当前文章。Admin 删除文章时必须同时保证详情、继续阅读和导入去重状态不产生悬空引用。

## 7. 图片上传与压缩

后台上传图片后，由 COS / 数据万象生成必要的派生图；生产主链路不让普通本地图片经过云服务器，云服务器只负责生成上传授权、确认处理结果和保存图片元数据。图片规格、处理标记、素材复用、历史兼容、前端选择与回退的唯一标准见 [《图片资产与封面处理规范》](./PRD-图片资产与封面处理规范.md)。

上传链路：

```text
后台上传图片
→ 后台向服务端请求 COS 直传任务
→ 服务端生成限时上传签名、原图 key、thumb key、medium key
→ 浏览器直接 PUT 原图到 COS
→ COS / 数据万象按 Pic-Operations 生成 thumb / medium
→ 后台通知服务端上传完成
→ 服务端保存图片 ID、文件名、URL、处理状态和元数据
```

业务流程与约束：

- 后台批量导入图册和手工文章封面均通过 COS 直传；公众号文章正文图和封面由服务端受控抓取后转存 COS。浏览器不为文章封面做本地裁切。
- 服务端校验图片类型与大小，生成限时签名；上传完成时校验图片 ID、文件名、URL 和大小，防止元数据串改。批量上传最多 3 路并发，单张失败可独立重试。
- 内容池只保存图片素材 ID 引用。保存图册或文章时，服务端必须校验所引用素材存在；取消、替换或移除的无引用临时素材按既有回收规则处理。
- 单图上传上限为 `5MB`，不额外限制原图像素边长；原图不在浏览器或 COS 处理链路中放大。头像继续使用独立的 `256 x 256`、客户端不超过 `100KB` 规则。
- 服务端不长期暂存图片文件，也不承接上传带宽或压缩 CPU；只保存素材元数据和 COS 地址。元数据至少包含文件名、尺寸、原图及派生图地址、各版本大小、处理状态、失败原因和处理标记。
- COS Bucket 必须允许后台域名的 `PUT`、`GET` 和所需请求头 `Authorization`、`Content-Type`、`Pic-Operations`；如启用 COS 上传回调，再按腾讯云要求配置 Callback 白名单。

处理状态使用 `pending`、`processing`、`ready`、`failed`。只有目标对象可读并完成登记后，图片才可作为正常可用素材下发；特殊的 `original-only` 正文图片按规范登记，不得误判为缺少派生图。

## 8. 分享设置

分享设置是所有小程序共用的全局资产。后台维护三个随机池：手记分享标题、手记分享封面文案、通用封面底图；不维护标签、排期或标题与底图配对。文章和心笺复用文案（text）类型的封面文案与封面样式，标题取公开内容自身，不读取手记标题库。后台还提供一组受限的封面样式参数，但不提供自由拖拽排版或自定义绘制能力。

### 8.1 手记分享标题库

- 标题按内容类型分为“文案、语音、图片”三个池；可逐条新增、编辑、停用或删除。
- 未保存全局分享设置时，后台初始标题库为：文案“分享一段文案，希望你喜欢”“给你写的句子，适合慢慢读”；语音“分享一段音频，慢慢听完吧”“为你录的音频，记得慢慢听”；图片“分享一组图片，想让你欣赏”“给你拍的照片，记得看一看”。
- 每条标题只表达内容类型和阅读期待，不得引用、保存或暗示手记的真实正文、图片内容或语音内容。
- 例如图片池可填写“今日图册已更新，打开看看”，文案池可填写“今天的手记已准备好”。
- 小程序按实际内容类型独立随机标题，并在本设备避开最近 12 次已使用标题。标题与封面文案、底图彼此不绑定。

### 8.2 手记分享封面文案库

- 封面文案同样按“文案、语音、图片”分池；每条限 4 至 20 个字。小程序固定大字号，每行最多 10 个字，超过时自动分成两行。
- 未保存全局分享设置时，后台初始封面文案库为：文案“点击阅读”“值得打开”；语音“今日音频”“值得听听”；图片“今日图册”“值得看看”。默认库仅用于初始化，调整默认值不覆盖管理员已保存的全局分享设置。
- 小程序会在封面中自动增加当日中文日期。单行文案时形成两行信息；两行文案时日期在上、两行文案在下。日期无需后台维护。
- 封面文案不能泄露具体内容；例如可使用“今日手记”“轻读片刻”“今日图册”“今日音频”。
- 小程序按实际内容类型独立随机文案，并在本设备避开最近 12 次已使用文案。

### 8.3 通用封面底图

- 底图通过现有 COS 直传批量上传、替换、停用和删除；底图采用专用的 `5:4` 派生规则，建议使用内容安全、主体清楚的横图。具体规格和低分辨率行为见 [《图片资产与封面处理规范》](./PRD-图片资产与封面处理规范.md)。
- 同一套底图用于手记文案、音频和未指定具体图册的首页轮换分享，以及公开内容没有图片时的默认封面；已打开图册的分享底图改用当前图册第一张图片。
- 小程序直接使用 COS 已生成的 `5:4` 底图，随机选择时避开本设备最近 8 次已使用底图。底图不与标题或封面文案一一绑定。

### 8.4 客户端合成与预览

- 分享图片由小程序在设备端合成，服务端只下发规则、文案池和 COS 图片地址；服务端不生成、不缓存分享 PNG。
- 手记分享图固定叠加当日中文日期和封面文案：文案、音频以及未指定具体图册的首页轮换使用通用底图；已打开图册使用当前图册第一张图片，图片不可用时回退通用底图。随机使用居中对称式或左对齐大标题式。封面不使用首页邮戳，也不展示标题。
- 后台可调整的样式参数仅包括：整体暗化遮罩（`0` 到 `0.4`，默认 `0.2`）和文字保护遮罩（`0` 到 `0.65`，默认 `0.1`）、日期与文案颜色、日期与文案字号、分割间距、分割线长度（均为 `20` 到 `100`，默认 `60`），以及两套内置排版的启用状态与纵向微调。分割间距统一控制日期行、短分割线和文案各行之间的视觉节奏。封面文案超过 10 个字时，小程序自动按“文案字号 + 分割间距 × 25%，四舍五入”计算折行行高；默认字号和分割间距均为 `60` 时，行高为 `75`，不额外提供后台设置。日期、文案、间距与分割线长度可独立调整，且至少保留一套排版。新增版式、绘制元素或自由坐标编辑仍需要小程序发版。
- 后台顶部“分享效果预览”固定展示 3 张，顺序为手记、文章、心笺；每次刷新时手记在文案、音频、图片三种类型之间轮换。预览使用当前启用的内置排版和样式参数，并优先使用真实通用底图；预览不代表服务器会产出图片。具体画布与导出规格见 [《图片资产与封面处理规范》](./PRD-图片资产与封面处理规范.md)。
- 小程序对手记底图默认加 20% 整体暗化遮罩，只检查文字预定区域的明暗与复杂度；明暗稳定的浅色区域使用后台定义的浅色底图文字色；深色或杂乱区域使用后台定义的深色/杂乱底图文字色和文字保护遮罩。不会分析正文或整张图片，也不要求管理员为每张底图打标签。

### 8.5 公开内容分享

- 心笺不进入手记标题库，分享标题固定按“第一句 → 第一段 → 前 50 字”提取；文章优先使用自身标题（最多 50 字）。两者均复用文案（text）类型的封面文案、日期、遮罩和两套排版样式。
- 文章使用自身 `coverImage`，绝不使用正文配图；无封面时，文章分享和文章列表按相同 `contentId` 稳定选择同一张通用封面底图，未配置才使用内置底图。当前心笺只有文案形态，始终优先使用通用封面底图，未配置才使用内置底图。具体图片版本、画布适配和失败回退见 [《图片资产与封面处理规范》](./PRD-图片资产与封面处理规范.md)。文章分享路径携带 `contentId` 并直接进入详情页。
- Admin 顶部“分享效果预览”固定展示手记、公开文章和公开心笺 3 张，顺序与 8.4 一致，优先使用已上传通用底图并可刷新轮换样本。

## 9. 广告设置

广告设置按当前小程序单独保存。

微信公众平台负责创建广告位并签发 `adUnitId`；Admin 负责把已经取得的 `adUnitId` 绑定到当前小程序的具体页面和场景，并控制业务开关。两者缺一不可。封面广告只在微信公众平台配置，不进入 Admin。

广告类型：

- 激励广告。
- 插屏广告。
- 原生模板广告。

不开放：

- 视频广告。
- 支付订单详情页广告。

广告位字段：

| 字段 | 必填 | 说明 |
|---|---|---|
| 广告位编码 | 是 | 系统唯一编码 |
| 广告位名称 | 是 | 运营可理解名称 |
| 广告类型 | 是 | 激励/插屏/原生模板 |
| `adUnitId` | 是 | 微信广告单元 ID |
| 开关 | 是 | 开启或关闭 |

额外字段：

| 广告类型 | 字段 |
|---|---|
| 激励广告 | 每天前 X 次免广告、激励广告弹窗提醒、无广告时视为看完 |
| 插屏广告 | 首次延迟和循环间隔（0–300 秒）；循环为 0 时仅一次，否则等待间隔及空闲条件后可再次展示 |
| 原生模板广告 | 首页插入模块位置；列表首个插入位置与后续间隔（1–100） |

首页至少配置：

- 首页手记激励广告。
- 首页打卡激励广告。
- 首页插屏广告。
- 首页原生模板广告。

后台广告页使用“首页”卡片统一管理首页原生模板、插屏、手记激励和打卡激励四个广告位。

心笺、我的页各自至少配置：

- 插屏广告位。
- 原生模板广告位。

文章至少配置：

- 文章原生模板广告、文章插屏广告两个文章列表页广告位。
- 文章详情激励视频、文章详情插屏广告两个文章详情流程广告位，其中激励视频支持每天前 X 次免广告、弹窗提醒和无广告放行；插屏采用延迟与循环间隔。
- 文章详情开头广告、文章详情正文广告两个原生配置项；正文广告可用于符合分段条件的中段、尾部和继续阅读列表，不存在第三个独立“中段”配置项。

## 10. 小程序设置

### 10.1 基础信息

字段：

- 小程序名称：默认正式名称为「轻读手记」。
- `AppID`。
- `AppSecret`。
- 开发者联系邮箱：用于当前小程序用户行使查阅、更正、删除和注销权利。
- 备注信息。

规则：

- `AppSecret` 只允许服务端保存和使用。
- 服务端通过 `AppID + AppSecret` 获取官方接口调用凭据。
- `Access Token` 按官方规则缓存和刷新。
- 联系邮箱按小程序独立保存，并下发给当前小程序的注销申请入口。
- `AppID / AppSecret` 从微信公众平台取得后填入 Admin；Admin 不负责生成或更新它们。
- 隐私保护指引、合法域名、类目、版本审核和正式发布只在微信公众平台配置；Admin 不保存对应状态。
- 小程序内“查看正式隐私保护指引”使用微信官方 `wx.openPrivacyContract()` 打开当前 AppID 在微信公众平台配置的正式页面。

### 10.2 实例绑定

- 小程序运行时取得自己的 AppID，并由服务端自动匹配 Admin 中唯一对应的实例。
- Admin 内部 ID 用于标识小程序实例、构造独立数据范围并记录数据来源或审计信息，不作为运营配置项；用户数据的实际读取边界由当前 `dataScopeId` 决定。
- 当前小程序绑定到一个内容池。
- 切换内容池后，该小程序立即使用新池内容和新池对应的用户数据，不把旧池用户数据迁入新池；切回旧池时恢复旧池原有数据。
- 分享模板为全局共享配置，保存后所有小程序立即使用新分享文案。
- 内容池和分享模板互不绑定；内容池是小程序实例参数，分享模板是全局参数。
- 每个小程序实例分别配置“私密图册”和“私密音频”，默认开启私密图册、关闭私密音频。关闭后服务端随机抽取和按类型分享均不得返回该类型；私密文案始终可用。
- 后台在同一设置区内，以“私密图册”和“私密音频”两个下拉框分别选择“开启”或“关闭”，不使用独立的二级卡片或开关控件。

### 10.3 跨小程序用户同步

统一用户方案：

- 服务端自建上层账号体系，内部生成 `accountId`。
- 能绑定微信开放平台的小程序优先使用 `unionid`。
- 不能绑定微信开放平台的小程序使用手机号兜底。
- `openid` 只用于单个小程序内识别。

同步规则：

- 内容池是用户数据的默认共享边界；运营不需要另外配置“用户空间”。
- 每个小程序只有`共享数据`和`独立数据`两种用户数据模式，默认使用`共享数据`。
- `共享数据`模式按`accountId + contentPoolId`读写。同一账号在绑定同一内容池且使用共享模式的小程序中，用户资料和使用记录保持连续。
- `独立数据`模式按`accountId + miniProgramId + contentPoolId`读写。即使多个小程序绑定同一内容池，独立模式小程序也不读取或改写共享数据及其他小程序的独立数据。
- 用户可见的昵称、头像、个人偏好、打卡、手记打开记录、30天防重复、点赞、收藏、分享、留言、阅读值、个人列表和个人统计均按上述数据范围同步或隔离。
- 广告配置与观看记录、页面访问、来源记录和后台运营统计始终按小程序独立，不因用户数据模式改变而共享。
- 登录时刷新当前数据范围，关键行为发生时实时写入当前数据范围；离线队列必须保存行为发生时的内容池、数据模式和范围标识，网络恢复后不得写入已经切换的新范围。

模式切换规则：

- 允许已经产生用户数据的小程序随时切换模式，但必须先完成数据迁移，再一次性切换读取范围；迁移期间继续使用旧模式。
- `独立数据`切换为`共享数据`时，把当前小程序、当前内容池的独立分支合并到该内容池的共享数据。共享数据为空时由独立分支直接播种；只有两边都没有数据时才从零开始。
- `共享数据`切换为`独立数据`时，为在当前小程序使用过该内容池的用户建立或更新独立分支，并保留切换时可见的完整状态，从切换完成后独立发展，不从零开始。
- 旧独立分支不得删除。小程序再次从共享切回独立时，将旧独立分支与该小程序共享期间可见的新变化合并，确保共享期间产生的数据不丢失，也不重复累计。
- 模式切换只处理当前绑定内容池，禁止借模式切换把用户数据迁到其他内容池。
- 重复执行迁移必须幂等，不产生重复行为或重复计数。
- 迁移全部成功后才更新小程序模式。任一步失败都保留原模式和原读取范围，不能出现部分用户已切换、部分用户未切换的状态。
- 后台在切换前和迁移状态中必须持续展示离线风险提示：服务端已保存的数据会按本节规则合并，用户设备中属于旧范围且尚未同步的离线留言、删除和互动可能在前端刷新范围时作废。

数据合并规则：

- 昵称、头像和个人偏好按字段使用`updatedAt`较新的值，不能用一项较新的资料覆盖整份资料。
- 打卡按业务日期去重；打开和分享按行为唯一标识合并；同一行为不得重复累计。
- 点赞、收藏使用该用户对该内容最后一次操作的状态。
- 留言以留言唯一标识合并；同一留言的删除标记优先于更早的正文，防止已删除留言恢复。
- 当日使用次数不得因切换模式重置；30天防重复根据合并后的有效打开记录重新计算。
- 阅读值、个人统计和公开互动数量不得直接相加，必须根据合并后的最终有效行为重新计算。
- 用户数据必须同时绑定稳定的内容唯一标识和内容池；不同内容池中相同的局部内容 ID 不得互相继承记录。

### 10.4 用户管理与手动注销

- 用户管理只展示当前选择的小程序账号。
- 收到用户通过小程序设置页提示的开发者邮箱提交的申请后，由开发者核实身份并手动注销。
- 注销当前小程序时，删除该小程序的登录会话、独立数据分支、广告记录、页面访问和来源记录，并解除该账号与当前小程序的关系。
- 共享数据按账号对数据范围的剩余归属处理：同一账号仍关联其他使用该共享范围的小程序时保留；当前小程序是该账号对该共享范围的最后归属时，删除该账号在该共享范围中的数据。其他账号的共享数据不受影响。
- 同一账号在其他小程序中的身份、仍由其他小程序持有的数据范围以及其他小程序的独立数据必须保留。
- 操作前二次确认，完成后写入操作日志；该操作不可撤销。

### 10.5 首页数据项显示控制

按小程序分别控制：

- 首页数据项按当前可见数量自动重排为 3 列、2 列或单列；全部关闭时前台不渲染该区域。

- 今天第几位。
- 已连续打卡。
- 累计阅读值。

### 10.6 文案设置

支持配置：

- 首页顶部文案。
- 心笺顶部文案。
- 文章顶部文案。
- 打卡按钮文案。
- 打卡前展示文案，多条。
- 打卡后展示文案，多条。
- 打卡广告未完整观看提示。
- 打开手记按钮文案。
- 手记打开前引导文案，多条。
- 打开手记广告未完整观看提示。
- 文章展开广告未完整观看提示。
- 文章、心笺 Tab 名称。
- 首页、文章、心笺 Tab 显示开关；顺序固定为“首页｜文章｜心笺｜我的”。
- 我的 Tab 固定显示、固定名称，不提供后台配置控件。
- 每日手记打开上限，默认 5，范围 0 到 9；`0` 表示不限次数。
- 私密图册：开启/关闭，默认开启。
- 私密音频：开启/关闭，默认关闭。
- 心笺排序方式：`random` 随机打乱或 `sequence` 按入库顺序倒序展示，默认 `random`。
- 文章排序方式：`random` 随机打乱或 `sequence` 按入库顺序倒序展示，默认 `random`。
- 留言功能：开启/关闭，字段名为 `messagesEnabled`，默认开启。

参数控件布局固定为两行：第一行依次为“单用户每日手记上限（0为无限）”“私密图册”“私密音频”，第二行依次为“心笺排序方式”“文章排序方式”“留言功能”。

模式切换默认值：

- 提审模式预设隐藏首页 Tab、关闭留言、关闭全部插屏广告、将全部激励广告位每日免广告次数设为 3，并将每日手记打开上限设为 0；正常模式预设显示首页 Tab、开启留言、开启全部广告位、将全部激励广告位每日免广告次数设为 0，并将每日手记打开上限设为 5。
- 模式切换只在后台界面填充上述预设值；切换后运营仍可手动调整任意字段，保存时提交当前表单值。服务端不因模式字段额外校验、强制关闭或强制开启留言、广告、首页或上限；重复保存同一模式也只保存当前值。

规则：

- 前端原样展示后台输入文案。
- 打卡、打开手记和展开文章各有一条“广告未完整观看提示”，字段分别为 `checkinAdIncompleteText`、`dailyContentAdIncompleteText` 和 `articleAdIncompleteText`，按当前小程序独立配置。
- 这些配置只用于用户提前关闭激励广告的场景；为空或获取配置失败时，前端分别回退到“完整观看广告后，即可完成打卡”“完整观看广告后，即可打开手记”和“完整观看广告后，即可展开全文”。
- “激励广告弹窗提醒”和“无广告时视为看完”都使用开启/关闭下拉框，按广告位独立保存，默认开启。
- 广告加载、展示或播放异常时，前端按“无广告时视为看完”决定直接继续或展示固定错误提示；网络异常、服务异常和业务规则限制仍由前端或服务端展示固定提示。
- 打卡前、打卡后展示文案分别保存为 `checkinBeforeTexts` 和 `checkinAfterTexts`，按当前小程序独立配置，后台均使用“每行一条”的文本框编辑，不要求包含中文逗号。
- 前端在当前设备每天分别选定一条打卡前、打卡后文案；同一天刷新不更换，次日优先避免与前一天重复。为空或获取失败时分别使用客户端默认文案包中的打卡前、打卡后两条文案池。
- 手记打开前引导文案保存为 `dailyContentPromptTexts`，按当前小程序独立配置，后台使用“每行一条”的文本框编辑。
- 每条手记打开前引导文案必须包含中文逗号 `，`，且逗号前后都必须有文字；前后字数不作固定限制。
- 前端按第一个中文逗号拆成上下两行，随机展示并尽量避免连续重复；该字段获取失败、为空或不合法时，回退到客户端默认文案池“想说的，都悄悄放这里了”“打开前，猜猜里面是什么”。
- 系统初始化的手记提示语为“想说的，都悄悄放这里了”“打开前，猜猜里面是什么”；打卡前为“今天也等到你了”“每天都来打卡吧”，打卡后为“今日已点亮，明天再来打卡吧！”“感谢你的支持，明天我等你哦！”。
- 后台显式清空列表时保存并下发空数组，服务端不补默认值；客户端整体回退内置文案池。列表文案及全局分享设置通过独立文案包下发，版本与覆盖规则见小程序 PRD 第 13 节。
- 不把按钮逻辑做成文案开关。
- 首页隐藏后，前台按“首页｜文章｜心笺｜我的”的固定顺序进入首个可见 Tab；“我的”始终保留为可见入口。冷启动必须在渲染首页业务内容前完成远端/缓存可见性解析，已隐藏首页不得短暂闪现。
- 留言客户端采用 fail-closed：只有配置明确返回 `messagesEnabled: true` 时才展示；字段缺失、配置请求失败或值为 false 时，前端隐藏首页、心笺和文章的留言入口及留言内容，并隐藏“我的”页的“我的留言”入口和列表内容，原有四个操作互动入口收敛为三个。
- Admin 保留远程启停能力；留言状态始终按 `messagesEnabled` 当前参数保存和生效，模式字段不额外强制关闭或开启。提审与实际上线配置应按平台要求保持一致。
- 达到手记打开上限时，前台提示“今天没有更多消息，请明天再试”。

## 11. 远程附件

远程附件为全局配置，所有小程序共享一套腾讯云 COS。

配置字段：

- `APPID`。
- `SecretID`。
- `SecretKEY`。
- `Bucket`。
- `bucket` 所在区域。
- `Url`。

规则：

- `SecretKEY` 只允许服务端保存和使用。
- 后台支持保存后测试 COS 连接。
- 所有内容池共用同一套远程存储配置。
- 图片上传后不只保存原图 URL，必须保存多尺寸版本 URL。
- COS / 数据万象在上传时持久化生成派生图，是图片压缩与分发的正式链路；访问时 CDN 缓存只能加速分发，不得改变本文定义的版本、裁切或处理标记。
- 音频上传后保存标题、原始文件名、对象 key、MIME 类型、大小、时长与 HTTPS `audioUrl`；小程序展示标题、用该地址直接播放，不通过应用服务器转存或完整下载。
- 用于小程序播放的 COS 音频地址必须属于微信已登记的合法下载域名，并应正确返回音频 `Content-Type`、`Content-Length` 和字节范围响应；长音频的边缓冲边播放以真机验证结果为准。

## 12. 留言与内容安全

留言来源：

- 首页手记、首页音频和首页图册留言（统一来源为 `daily_content`）。
- 心笺留言（来源为 `letters`）。
- 文章留言（来源为 `article`）。

留言长度上限为 200 个计数单位，ASCII 计 1、非 ASCII 计 2；不是任意 200 个中文字符。

后台能力：

- 查看。
- 搜索。
- 删除。
- 按来源筛选。
- 按小程序筛选。

数据字段：

- 留言 ID。
- 小程序 ID。
- 访客 ID。
- 统一账号 ID。
- 来源页面。
- 来源内容 ID。
- 留言内容。
- 安全检测状态。
- 创建时间。

内容安全最简方案：

```text
用户提交留言
→ 服务端调用 security.msgSecCheck
→ 安全内容自动放行
→ 违规内容自动拦截
→ 可疑内容第一版可按拦截处理
```

上线强制要求：

- 文本检查开启时，生产类环境由服务端调用微信文本安全接口；缺少凭据或检测失败拒绝提交。当前后台仍可关闭远程文本检查，关闭后非拦截词内容以 `unchecked` 通过；拦截词检查仍先执行。不得把现状描述为不可关闭的强制远程审核。
- 前端不得绕过服务端直接信任本地判断。
- 留言保存前必须等待检测结果。
- 检测失败或接口异常时，第一版按“提交失败，请稍后再试”处理。

后台最少提供：

- 文本安全检测开关。
- 图片安全检测配置占位；当前未接入实际图片审核，不能把开关状态当作审核完成。
- 当前处理模式说明。
- 已通过/已拦截/待复查数量汇总。
- 留言管理页查看命中状态。
- 操作日志记录自动拦截和人工处理结果。

## 13. 数据库版本与活动库边界

- 当前且唯一支持的结构为 schema v6。新库直接初始化完整 v6 结构；现役代码、接口和客户端只认 `articles` / `article`，不保留 `diaryEntries`、`diary`、日记页面或旧字段兼容分支。
- 每个配置的数据目录只使用一个活动主数据库 `secretbox.sqlite`；本地默认目录为 `admin/server/data`。`secretbox.sqlite-wal`、`secretbox.sqlite-shm` 是运行时伴生文件，不是第二个数据库。
- 当前源码只接受 v6；历史记录中的线上迁移结论不作为本次核验结果，实际数据库版本需在授权的运维检查中确认。
- 仓库保留的 `npm run db:migrate` 仅是受控的离线 v5→v6 工具，用于经明确确认的旧活动库输入；不得对当前生产库重复执行，不得加入应用启动或日常发布流程。
- schema v6 不保留旧字段、旧接口、旧客户端兼容分支或 v1-v4 迁移工具。旧版数据库及迁移源只能作为冻结资料保留在本地 `archive/`，不得进入现役代码、活动数据目录或生产恢复流程。
- 应用启动只验证 v6，不自动迁移或改写非 v6 数据库。具体生产主机、存储资源和操作步骤只在本地部署手册维护，不进入公开 PRD。

## 14. 后台验收标准

后台需提供“服务配置检查”能力，至少检查：

- 当前小程序 `AppID / AppSecret`。
- 当前绑定内容池，以及全局分享模板是否完整。
- 手记、心笺、文章内容是否为空。
- 图片素材是否有可用 URL。
- COS 配置是否完整。
- 已开启广告是否缺少或使用无效格式的 `adUnitId`；开发者邮箱和代码上传通道是否就绪。
- 文本安全配置状态；图片审核不作为已实现的检测能力。
- 图片是否仍处于“原图直用”或缺少 `thumb / medium` 的异常状态。

该检查只覆盖 Admin 和服务端能够确认的项目，不代表微信审核通过，也不读取微信公众平台的审核、发布、隐私或合法域名状态。提交审核前，开发者仍需在微信公众平台完成隐私保护指引、服务器域名、业务域名、类目和版本提交；微信公众平台是这些事项的唯一状态来源。

## 15. 存储配置边界

- 全局 COS 配置由 Admin 保存，初始化的存储桶、地域、域名与密钥为空；不把某个线上桶或域名写成产品默认值。
- 上传需要服务端限时签名；普通图片浏览器直传，公众号远程图和音频由服务端处理后上传。音频标准化与图片派生是两条不同链路。
- 图片派生规格以[图片资产与封面处理规范](PRD-图片资产与封面处理规范.md)为准。CORS、权限、域名和费用属于具体环境配置，不在公开 PRD 记录真实资源清单或历史价格结论。

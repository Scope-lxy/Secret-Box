# 文章文档批量导入规范

状态：**已实现，本地验收完成**。确认与实现日期：2026-09-13。生产发布另行执行。

目标：将 `wechat-article-capture` 已整理好的文章 MD，直接批量导入指定内容池。正常文件无需修改格式、逐篇填写字段或再次调用 AI；运营检查预览后一次确认导入。

依据：[此前讨论](codex://threads/01a0830c-319a-7582-becb-44736aa0ff9d)、[当前后台 PRD](PRD-轻读手记后台.md)、[现有导入实现说明](TEC-content-import.md)、[图片资产规范](PRD-图片资产与封面处理规范.md)，以及采集 skill 当前导出的真实 MD。本文件是文章文档导入的产品规则真源；接口、实现和验证记录见导入说明，后台总入口和视觉规范分别见后台 PRD 与后台设计规范。

## 1. 用户操作与交付范围

完整流程：**采集 skill 导出 MD → 后台选择文章文件夹 → 自动识别、去重和准备图片 → 检查预览 → 确认导入**。

- 文章导入使用“导入方式”下拉框，默认“文件导入”，可切换为“链接导入”；下拉框复用文案手记的控件样式，置于输入卡片内，不新增第二层导航。两种方式共用阅读预览样式和文章编辑器。首次进入页面继续为空白，不自动加载旧文章。
- 首张输入卡片统一为 300px 高，与文案、音频、图册、心笺的输入卡片一致；切换类型或导入方式时，下方预览卡片的起始位置保持一致。链接输入框、文件夹拖入区和状态区填充剩余空间，长内容、进度及恢复操作在卡片内部滚动，不撑高整张卡片。
- “选择文件夹”位于输入卡片标题栏右上角，与链接模式的抓取按钮共用主操作位置；“下载格式模板”放在标题下方的说明中，与说明同字号，以主题色区分，切换至链接导入时隐藏。
- 文件导入可点击“选择文件夹”、点击整块浅暖色区域或拖入文件夹；区域也支持键盘 Enter / Space，处理中禁止重复选择。区域内只显示简短操作与格式 / 子目录提示，数量和大小限制保留在标题下。单篇或少量文章可用链接导入。选择上级文件夹后递归读取全部子目录中的文章，无需逐个选择子文件夹。界面、代码示例和说明使用通用目录名称，不列举真实账号。保留相对路径用于问题定位，同名文件不互相覆盖。
- 第一版接受 `.md`、`.markdown`、`.txt`，一份文件始终对应一篇文章。正文中的空行、序号和 `---` 不拆成新文章。
- 每批最多 **200 篇**，后台自动分组处理，用户不需要每 20 篇重新选择。原有 URL 抓取的 20 条限制不随本功能扩大。
- 原始文本单文件上限 1MB，一批原始文件合计上限 20MB；超过时明确提示，不悄悄截断文件或只读取前 200 篇。传输分组同时按字节限制，避免将整批塞进现有单个请求。
- 采用 UTF-8，兼容 BOM、Windows 换行；TXT 沿用现有常见中文编码兼容逻辑，解码异常显示文件名和原因。
- 选择文件夹只识别文章扩展名；跳过隐藏辅助目录、`.article-capture` 及非文章文件并显示跳过数量，不把采集报告、JSON 和缓存混入文章。
- 内容池沿用进入页面时的明确选择；开始后固定目标内容池。账号子目录用于组织来源，不据此自动创建内容池或给文章分类。
- 第一版不处理 ZIP、本地相对路径图片包、Word、PDF、音视频转录、历史文章自动覆盖或全新任务中心。其他平台已整理好的标准 MD 可以走相同文档入口，不因此宣称后台具备对应平台的网页抓取能力。

## 2. 已确认的关键取舍

| 取舍 | 当前规则 |
| --- | --- |
| 统一改成文首 YAML 字段 | 首选“可读文章 + 文末原文链接”，不要求任何隐藏标识；兼容早期 JSON 和 YAML，旧样文仍可识别 |
| 每批最多 20 篇 | 文档导入最多 200 篇并自动分组；原有 URL 抓取限制独立保留 |
| 导入来源 | 选择或拖入上级文件夹，递归读取 MD / Markdown / TXT；单批最多 200 篇 |
| 再附一段 AI 导出提示词 | 直接提供当前 skill 格式的下载模板和简短说明，日常使用现有 skill 即可 |
| 无封面时把正文首图作为候选 | 默认沿用文章无封面时的现有通用底图，不自动挪用正文图片 |
| 图片失败后提示处理 | 文档模式保留失败图片的位置与原因；该篇进入“需处理”，明确处理后才能导入 |
| 根据来源链接去重 | 同时识别平台文章身份、不同分享参数、旧 URL 导入记录和无来源文件的内容重复 |
| 复用原有抓取后处理 | 复用图片存储、预览和保存；已清理正文不再次执行抓取入口的语义清理或装饰图过滤 |
| 异常处理 | 正常项可先确认；剩余草稿支持在 24 小时内主动恢复并继续修复 |

## 3. 文件识别与正文分离

### 3.1 首选格式：当前 skill 输出

文件开头依次为可选封面图片、一级标题、`账号名称丨发布时间` 和正文；文末只用分隔线加完整原文链接，不附 JSON、隐藏文章标识、抓取 / 清理时间或内容哈希。

```markdown
![封面](<封面URL>)

# 文章标题

账号名称丨2026-09-13 09:30:00

正文内容。

---

原文链接：<原始URL>
```

| 文档信息 | 后台用途 |
| --- | --- |
| 文首一级标题 | 文章标题 |
| 文首账号时间行中的账号 | 后台 `author`；界面标为“账号 / 作者” |
| 文首账号时间行中的北京时间 | 原始发布时间；转换为 UTC 保存，预览仍按北京时间展示 |
| 文首独立封面图片 | 独立封面素材，不重复插入正文 |
| 文末原文链接 | 保存原始出处；后台从 URL 识别平台、计算规范来源和文章身份，不把这行保存为正文 |

去重需要的文章身份和内容指纹全部由后台生成、保存在后台；不用 skill 预先生成或嵌入 MD。

解析要求：

- 正确识别带尖括号的图片地址，例如 `![封面](<https://example.com/cover.jpg>)`，以及普通内联图片、引用式图片和图片外包链接；普通文字链接不自动变为图片。
- 只拆出文件最前面的文章封面、标题、账号时间行，以及文末“分隔线 + 原文链接”；保留正文自己的小标题、分隔线、图片、引用和代码示例。正文中间或代码围栏里的同名示例不当作文件信息。
- 后台只将拆出的正文保存为 `bodyMarkdown`。图片转存后只替换图片目标地址，保留段落和 Markdown 结构，避免通过整篇 HTML 往返转换造成格式损失。
- 标准文件以文首当前可读字段为准；时间按北京时间解析。用户修改标题、账号、时间或正文后，按修改后的文件处理，不要求同步第二份信息。无法确定哪一部分属于文章头时进入“需处理”，不猜测删除正文。
- 内容指纹使用实际正文重新计算，不依赖文件提供的哈希，也不恢复或覆盖用户修改。
- 缺少文末链接时走兼容解析；已明确声明原文链接但 URL 无效时显示具体问题。识别后的资料区不渲染到正文。

### 3.2 兼容格式

兼容此前建议的 YAML 文件头字段：`title`、`author`、`publishedAt`、`sourceUrl`、`cover`，以及早期 `article-capture:v1` JSON 注释。旧资料只作缺失字段的补充，优先使用文首当前可读值；旧的身份和正文哈希不直接作为可信去重结果。仅解析普通数据值，不执行对象标签或表达式。明确标记的旧资料损坏时显示可修复问题，不把 JSON 当正文。

普通 MD 优先从首个文章标题识别标题，找不到时用去掉扩展名的文件名作待确认标题；不按文件名中的连字符擅自拆账号。纯 TXT 作为单篇文本处理，只有明确符合模板的开头才拆出字段，不把第一段长正文擅自改为标题。未声明来源不强制补链接。

标题、账号 / 作者、原始发布时间和非空正文是确认导入的必填信息。缺少字段时允许预览和编辑，但只阻止对应条目。无法确认的日期或时间不使用当前时间兜底。没有声明封面不算错误，沿用现有无封面展示规则。

首版不默认根据文件夹名猜账号、不推断发布日期；来源一致的一组缺失字段可在预览中批量补充账号，发布时间仍逐篇核对。

## 4. 清理与排版职责

采集 skill 已完成“Admin 移植规则清理 + AI 文本残留检查”。**文档导入默认按文件现有正文导入，不再次调用 AI，也不重复执行推广尾部、署名来源或批次模板清理。** 普通兼容 MD/TXT 同样不自动改写；需要清理时在导入前使用 skill 或在预览中编辑。

后台仍负责必要的内容校验和安全渲染，支持标题、段落、加粗、斜体、删除线、引用、列表、图片、链接、分隔线、行内代码和围栏代码。不执行文件里的 HTML、脚本或自定义样式。

简单 Markdown 表格纳入首版兼容：保留表头、行列顺序和单元格内容；后台预览与小程序阅读一致，不能变成混杂的散行文字。表格在容器内换行适配，不能撑宽卡片。复杂布局、公式扩展、脚注扩展和嵌入媒体不宣称完整支持，识别到影响阅读的内容时显示具体提示。

文档模式不复用 URL 抓取中按小图尺寸、首尾图片比例判断装饰图的删除策略，避免再次删除 skill 已保留的必要图表。没有文字线索的纯图片广告可能保留，这是当前低 token 成本流程的已知边界，后台不通过新增逐图 AI 审核弥补。

## 5. 图片准备与失败处理

- 导入准备阶段读取封面和正文图片的原图 URL，经现有受控下载链路转存 COS；正常文件无需提供本地图片附件或打开浏览器扩展。
- 图片按现有规范生成展示版本，以原始字节哈希和处理标记复用素材；同一任务内相同地址合并处理，相同图片在不同正文位置仍原位保留。
- 沿用当前 5MB 单图限制、静态图完整构图、正文动画和长图保留原图的规则。图片仍需遵守协议、域名解析、重定向、文件类型和大小校验，不将文档中的地址直接当作可信资源。
- 重试只处理失败图片，不重新读取原始文章、不再次上传成功素材。正常网络错误做有限自动重试，持续失败时保留明确的单图失败项。
- 已声明的封面或正文图转存失败时，该篇进入“需处理”。预览保留占位及图片序号，可选择“重试”“本地替换”“移除该图”；处理完成后恢复为“可导入”。不自动把失败图片从正文抹掉。
- 用户原本未提供封面，或主动移除失败封面时，使用现有通用底图逻辑；不自动把正文首图变为封面。
- 文件中的本地磁盘路径、相对路径及 Base64 图片在首版提示不支持；不尝试读取服务器同名路径。需要本地图片时可在问题处理处明确选择替换文件。
- 最终正文和封面只引用已登记的项目素材，不把转存失败的微信图片外链当成已经准备好的图片保存。

图片属于按需加载的普通资源，不引入 AI 图片分析费用。图片实际存储和流量按现有 COS 计费。

## 6. 去重：后台从 URL 和实际正文生成

### 6.1 检查范围与时机

在**同批文件**和**目标内容池已有文章**中检查重复；已有文章包括 URL 抓取、文档导入及手工新增的记录。其他内容池独立判断。

解析后、图片下载前先做一次去重，减少明显重复文章的图片请求；确认写入时在服务端再次检查，防止两个任务并行或网络重试造成重复追加。

### 6.2 判断优先级

| 依据 | 行为 |
| --- | --- |
| 后台从来源 URL 计算出相同的平台文章身份 | 明确重复，默认跳过，即使文件名、标题或正文修改也不自动新增或覆盖 |
| 相同的规范原文链接，或与旧记录来源链接对应 | 明确重复，默认跳过 |
| 无法用来源确定，但账号、标题和后台重算的完整文档内容指纹相同 | 文档重复，默认跳过；不因文件名不同而重复导入 |
| 只有标题、账号、正文文本相似，图片或来源对应关系不确定 | 标记“疑似重复”，查看已有文章后选择保留为新文章或移除；不自动覆盖 |

微信长链接按 `__biz + mid + idx` 建立身份，忽略 `sn` 及分享追踪参数差异。短链接保留稳定路径并剔除追踪信息。只有文档和现有记录能建立对应关系时，才能把长短链接认作同一文章；不会为了去重重新抓取微信页面，更不会仅凭标题相同武断合并。

不要求文档包含 `source_id`、内容哈希或任何隐藏字段。后台校验原文 URL 后计算文章身份，并按实际正文计算内容指纹；图片地址替换为 COS 地址前保留导入时指纹，使同一文档再次导入仍能识别。改变文件名不改变判重结果。

旧文章当前的 `sourceHash` 来自最终页面 URL 的哈希，与新的平台身份算法不同。兼容历史记录时，从保存的 `sourceUrl` 计算新身份；保留原内容 ID 和旧哈希，不通过删库或重新导入迁移。旧记录缺少可匹配来源、且图片已转成 COS 时，正文相同最多作为疑似重复依据，避免误合并。

同来源文件有修改时提示“已有文章，文件内容可能有更新”，可打开已有记录查看；第一版更新仍走现有文章编辑功能，不提供自动覆盖。新增字段至少保留规范来源身份和导入内容指纹，并在保存、编辑及去重链路中统一维护。

## 7. 预览、确认与继续处理

- 上方显示本批文件数、准备进度、可导入、需处理、重复和失败数量；支持“只看需处理 / 重复 / 失败”、按标题或账号搜索。文件名在问题详情中可查，不抢占正常阅读内容。
- 复用手机阅读卡片和双栏编辑器；卡片以 1200px 页面宽度下约 314px 的尺寸为基准固定宽度，列数随可用空间自动增加，可排下 4、5、6 张时按相应列数显示，卡片不随窗口继续放大。文件与链接导入采用相同布局。每页 18 篇，图片延迟加载；分页只影响浏览，确认范围仍为整个任务的可导入条目。
- 正常条目默认保留，不要求逐篇勾选、点击确认或重新做 AI 审核。编辑和移除继续只影响本批草稿。
- 缺字段、身份冲突、疑似重复和未解决图片失败都进入“需处理”。单篇异常不拖住其他文章；“确认导入”提交本批全部可导入条目，并在按钮附近明确本次范围。
- 确认成功后移出已导入项，重复项给出跳过结果，异常项继续保留以便修复后再次确认；不因部分成功就删除整个未完成任务。
- 草稿编辑、移除状态和成功结果在服务端保存，网络中断后重试不会新增重复条目，也不会恢复已移除文章或覆盖运营编辑。
- 当前页面查询中断时直接重试原任务。再次进入页面保持空白；仅在目标内容池存在未完成文档任务时提供“继续未完成导入”入口，用户主动选择恢复。
- 文档草稿按最后有效处理或编辑时间保留 24 小时，单纯查询不延长保留期。服务重启后将中断条目标为可继续，并按成功记录续处理，不伪装成已经完成。
- 全部完成、主动放弃或过期后清理临时文档和无引用图片，复用素材仍被文章或其他任务引用时不得误删。导入内容保存到当前内容池；确认前不成为小程序可读的正式文章。
- 重新选择一批来源替换当前批次；存在未保存编辑或进行中的任务时，沿用页面的放弃操作确认。成功后停留在导入页，可继续选择下一批。

这里的草稿是导入任务临时状态，不新增内容管理的发布审核流。文档任务的恢复与部分确认属于本次新增能力；URL 抓取入口的空白进入、抓取限制和清理行为保持各自规则。

## 8. 实现边界

当前按“文件识别 → 统一文章草稿 → 去重 → 图片准备 → 预览编辑 → 确认保存”处理，浏览器上传的是文档内容及相对路径；服务端不会按文件路径读取服务器磁盘。文档输入不调用公众号页面抓取，不连接 BrowserSkill 或 Playwright，无需新增浏览器扩展或配置模型 API。

文档与链接抓取使用各自的任务规则，共享现有存储、权限、文章编辑器和素材生命周期。文档模式保留失败图片位置、部分确认和显式恢复；URL 模式保留原有清理及一次发布流程。

资料先从文档拆出再渲染，文首和文末信息不会混入正文。正文只保存 Markdown，安全 HTML 按需派生；简单表格在服务端及小程序阅读层保留结构。身份与指纹在后台生成，历史内容无需重建或重新导入。

全部完成后清空临时正文、图片槽位和任务素材引用，保留简短完成记录用于幂等确认和结果展示；记录也受 24 小时保留期约束。主动放弃、过期和移除按现有引用检查回收未使用素材，包括本地上传的替换图。

文件夹递归读取按浏览器实际授予的文件范围执行；隐藏辅助目录不作为文章来源。拖拽目录会持续读取目录列表，避免 Chromium 每次返回最多 100 个目录项造成遗漏。图片来源必须可正常访问，COS 配置及其自定义域名的 HTTPS 证书必须有效。

## 9. 验收标准

1. 当前采集 skill 的 10 篇真实 MD，无需改名或改格式即可识别标题、账号、原始时间、封面和正文；辅助信息不出现在阅读内容中。
2. 单次选择 200 份文档可以自动分组处理并分页预览；201 份明确提示超限。一个损坏文件不影响其他文件完成准备。
3. 同文件改名、相同长链接更换分享参数、与已有 URL 导入记录相同的来源，都不重复新增；已确认项目因请求重试不会再插入。
4. 同一来源改正文会提示已有文章；无来源同内容可去重；无法建立对应关系的长短链接只提示疑似重复，不误覆盖。
5. 不包含任何隐藏标识、抓取时间或哈希的精简 MD 可直接识别并去重；手动修改 MD 后按当前文件内容预览。缺账号或时间只阻止对应条目，不使用当天日期冒充发布时间。
6. 标题、引用、列表、代码、正文图片位置、图注和简单表格在后台及小程序中保留结构；文档模式不再次删除推广区以外的正文图或重新调用 AI。
7. 图片先转存并复用素材；失败图片在预览中仍有位置和原因，重试不重传成功图片；处理后可导入，没有封面时走既有底图规则。
8. 正常项目可先确认，剩余异常项可继续修复；查询中断、重复提交、离开后主动恢复和服务重启都不丢失已保存编辑或重复导入。
9. 移除、放弃、过期和文章编辑后的图片回收遵守引用关系；历史 URL 导入、普通内容导入及当前内容池隔离通过回归验证。
10. 交付时执行现有 `npm test`、`npm run verify:miniapp`，并进行文件夹选择、预览编辑、图片失败及小程序阅读的实际验收。真实图片转存测试使用明确的测试内容池，不把采集成功当作后台转存已成功。

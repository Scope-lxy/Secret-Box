# 批量导入统一体验方案

状态：**第一阶段已落地：文章 URL 抓取与 MD / Markdown / TXT 文件导入已统一**。核对日期：2026-09-14。

本轮优先级：**先统一文章的“文件导入”和“链接导入”，再以文章导入为基准统一文案、音频、图册和心笺。**

## 1. 先回答本轮核心问题

目前“确认导入全部 X 篇”**不是所有导入类型共享的机制**。

当前后台有三套相近但不完全一致的实现：

1. **文案手记、音频手记、图册手记、心笺**共用普通批量导入组件。右上角单独显示“X 条可导入”，主按钮只写“确认导入”；有错误时显示“X 条需处理”，并禁止提交。
2. **公众号 URL 抓取**使用文章管理器自己的组件。右上角单独显示“X 篇可导入”，主按钮仍只写“确认导入”；失败、重复和作者缺失通过另一段辅助文字表达，重复文章保留在预览列表中，状态集中在元信息条。
3. **文章文件夹导入**使用文档导入组件。右上角主按钮直接写“确认导入全部 X 篇”，摘要同时显示总数、可导入、需处理、重复、失败和已导入数量；重复文章在卡片内显示处理提示。

因此，用户看到的差异不是导入本质不同，而是任务状态、数量和操作反馈没有使用同一套界面语言。图 1 中的黑色“已导入 26 篇”是一次操作完成后的临时 Toast；图 2 中的米色区域是重复状态提示，两者也不属于同一层级。

文章的两种方式真正只有来源不同：**链接导入由后台实时抓取公众号 URL；文件导入读取已经抓取好的 MD / Markdown / TXT。** 两者之后都应该进入同一个“文章任务”：同一套准备状态、同一套预览卡片、同一套重复提示、同一个确认按钮、同一个原始来源展示和同一套保存结果。

## 2. 当前“内容类型 × 导入方式”清单

| 内容类型 | 当前主要入口 | 可用来源方式 | 当前解析 / 处理方式 | 当前重复处理 | 当前预览与确认表现 |
| --- | --- | --- | --- | --- | --- |
| 文案手记 | 导入内容页 | 文件夹；TXT 直接选文件为辅助入口 | TXT 按自动识别、序号、空行或分隔线拆分，每段一条 | 同批和目标内容池按正文去重，重复项在预览前移除，摘要显示“跳过 X 条重复内容” | 普通列表预览；目标按钮为“确认导入全部 X 条” |
| 音频手记 | 导入内容页 | 文件夹；MP3/M4A 直接选文件为辅助入口 | 每个音频文件一条，读取时长，上传后统一响度 | 不做内容级去重；上传失败可单独重试 | 普通列表预览；目标按钮为“确认导入全部 X 条” |
| 图册手记 | 导入内容页 | 文件夹 | 按子目录或文件名序号分组，每组最多 9 张 | 不做图册内容级去重；同图按素材哈希复用，失败图片可重试或移除 | 普通列表预览；目标按钮为“确认导入全部 X 组” |
| 文章（文件） | 导入内容页的“文件导入” | 文件夹，递归读取 MD / Markdown / TXT | 逐篇解析标题、作者、发布时间、封面、正文和原文链接，统一执行 Markdown 营销内容清理，准备图片后预览 | 按规范来源身份或正文指纹判重；重复项自动跳过 | 文档预览组件；摘要和元信息条与 URL 模式统一，按钮为“确认导入全部 X 篇” |
| 文章（链接） | 导入内容页的“链接导入” | 每行一个公众号 URL | 异步抓取公众号文章，清理推广尾部，转换为统一阅读预览 | 按规范来源身份或正文指纹判重，重复项自动跳过 | URL 文章组件；摘要、元信息条和按钮与文件模式统一 |
| 心笺 | 导入内容页 | 文件夹；TXT 直接选文件为辅助入口 | TXT 分段，每段一条，默认归入“默认”标签 | 同批和目标内容池按正文去重，重复项在预览前移除 | 普通列表预览；目标按钮为“确认导入全部 X 条” |

本表中的“文件夹 / 直接选文件 / URL”是来源方式；“文案、音频、图册、文章、心笺”是内容类型。统一界面时只统一任务框架和视觉表达，不把文章 URL 抓取变成其他类型的能力，也不改变各类型的解析、限制和判重规则。

## 3. 统一目标与优先级

用户无论导入哪种内容，都按同一条心智路径操作：

**选择来源 → 读取或抓取 → 准备并检查 → 查看预览 → 处理异常 / 重复 → 确认导入整批可导入项**。

### 第一优先级：统一文章的两种导入方式

文章文件导入和文章链接导入都进入同一个任务状态模型：

```text
已提交来源 → 准备中 → 可导入 / 需处理 / 重复 / 失败 → 确认导入 → 已导入
```

两种方式的差异只出现在“来源准备”阶段：

| 阶段 | 文件导入 | 链接导入 | 统一后的表现 |
| --- | --- | --- | --- |
| 提交来源 | 选择文件夹并上传文档内容 | 粘贴 URL 并创建抓取任务 | 同一来源输入区，主按钮均在右上角 |
| 准备内容 | 解析文档字段、统一识别并清理营销内容、准备图片 | 抓取网页、统一识别并清理营销内容、准备图片 | 同一条“准备中 X/Y”进度信息 |
| 形成预览 | 文章正文和文件信息 | 文章正文和 URL 信息 | 同一张文章阅读预览卡片 |
| 判重 | 来源 URL / 文档内容指纹 | 公众号文章身份 / 来源 URL | 同一条简短重复提示 |
| 确认保存 | 写入文章与来源信息 | 写入文章与来源信息 | 同一个“确认导入全部 X 篇”按钮 |

文章卡片上方统一预留一条很矮的“元信息条”，它紧贴预览卡片、保持一行高度，不另起文件信息卡，也不在预览卡片底部再追加一块重复提示。元信息条默认只承载来源和当前状态；发生自动清理时，允许增加一个唯一的纯文字操作：

- URL 导入：直接显示原始 URL；过长时单行省略，原始链接本身不增加操作。
- MD 导入：只显示文件名，例如“晨间散步.md”。不向运营展示相对路径，也不展示文档内的原文 URL。
- 发现重复或需要处理时，在同一条元信息条的状态位置显示简短提示，例如“重复，已跳过”或“已自动处理”；这些状态不增加操作。
- 自动清理营销内容时，显示简短状态“已清理营销内容”，并提供蓝色纯文字操作“恢复”；没有发生清理时不显示该操作。
- 来源和状态可以在同一行左右分区显示，但不改变下面的阅读预览卡片结构。

后台仍可保存来源类型、原始 URL、文件名和判重所需的技术字段；这些字段用于去重、审计和重试，不等于都要展示给运营。保存后的文章只在已有文章信息区域按同一规则展示“链接”或“文件名”，不要求新增来源抽屉或新的编辑区。

### 第二优先级：以文章导入为基准统一其他四种内容

文章两种方式完成统一后，再把相同的任务框架迁移到文案手记、音频手记、图册手记和心笺。它们只替换来源控件、预览主体和类型专属处理，不重新设计另一套确认和状态逻辑。

统一应覆盖四件用户能直接感知的事：

- 输入卡片的标题、说明、主按钮位置和来源方式控件位置一致。
- 预览卡片标题栏的摘要、状态数量、主按钮位置和按钮句式一致。
- 单条内容的状态提示、重复提示、编辑 / 重试 / 移除操作位置一致。
- 读取中、准备中、可继续、完成、失败和重复提交的反馈层级一致。

统一不改变以下内容：

- TXT 如何分段、音频如何处理、图册如何分组；文章现有营销识别规则保持不变，只统一到两种文章入口。
- 各类型的文件格式、单文件大小、单批数量和 URL 域名限制。
- 哪些类型参与内容级去重，以及文章规范 URL / 正文指纹的判定结果。
- 图片和音频的上传、重试、素材复用及回收规则。

## 4. 文章优先的统一页面结构

### 4.1 文章页面级

页面保留现有内容类型 Tab。文章 Tab 内继续保留“文件导入 / 链接导入”切换，但切换只替换来源输入区，不替换预览卡片、摘要栏、状态条和确认区域。

文章的两种导入方式继续使用当前来源输入区和当前文章预览卡片结构。统一只做三件事：

1. 来源输入区的主按钮、进度和错误提示使用同一套位置与文案规则。
2. 每张现有预览卡片上方增加一条一行高的元信息条，显示文件名 / URL 和状态。
3. 预览卡片内部的阅读排版、编辑、删除和重新抓取按钮保持现有结构、位置和交互，不因统一方案重新设计。

输入区继续使用当前约 300px 高度。URL 文本框和文件夹拖入区只替换内容，不改变预览卡片的起始位置。

### 4.2 文章预览卡片标题栏

两种文章导入统一使用：

```text
导入预览
共 28 篇 · 可导入 26 · 需处理 1 · 重复 1 · 失败 0 · 已导入 0
                                                                  [确认导入全部 26 篇]
```

文件导入当前已经接近目标形态；URL 导入需要补齐“全部 X 篇”、失败 / 需处理数量和已导入数量。按钮的数字始终是整个任务的可导入数量，不受当前分页、筛选或已展开卡片影响。

### 4.3 文章卡片上方的元信息条

文章阅读卡片本身保持现状。卡片上方的元信息条固定为一行，左侧显示来源，右侧显示状态文字；只有自动清理状态可以在文字后放置“恢复”这一项蓝色纯文字操作。不再把文件名放在卡片上方一块、重复信息放在卡片下方另一块。

示例：

```text
晨间散步.md                                      重复，已跳过
https://mp.weixin.qq.com/s/abcdef…                 可导入
周末阅读.md                                      已清理营销内容  恢复
```

重复提示使用图 2 中的米色视觉语气，但压缩到元信息条的状态区域，只展示一条短文本，不增加操作。恢复操作只属于自动清理提示，不扩展到重复、失败或缺少作者 / 时间等其他状态：

- `重复，已跳过`（规范 URL 或正文指纹命中）

原始来源展示和重复提示均不改变文章正文，也不触发自动覆盖。重复提示不新增弹窗，不移动或改造卡片右上角的编辑、删除、重新抓取按钮。

### 4.4 文章来源信息的保存口径

两种文章方式都保存一条不可被正文编辑覆盖的“原始来源”记录，至少包含：来源类型、原始来源值、可读名称、规范化来源（如有）和导入时间。

- URL 模式保存用户提交的原始 URL，并可额外保存规范化 URL 用于判重；界面直接展示原始 URL。
- MD 模式保存原始文件名；相对路径和文档内原文 URL 可以作为后台技术字段保存，但界面只展示文件名。
- 导入任务保留原始文档内容用于当前批次查看和恢复；是否长期提供“下载原始 MD”属于实现阶段的存储决策，不改变本轮的一行元信息展示。

两种方式都通过同一个“来源 + 状态”元信息条展示，不新增来源弹窗，也不让运营在不同位置寻找文件名、链接和重复原因。

### 4.5 元信息条的优先级与颜色

元信息条只保留一行，但状态必须有优先级。优先级决定颜色、是否计入“可导入”和是否允许确认：

| 优先级 | 颜色建议 | 典型状态 | 是否可导入 | 展示逻辑 |
| --- | --- | --- | --- | --- |
| 阻断 | 红色 | 规范 URL 或正文重复、文件读取失败、URL 抓取失败、正文无法解析、图片准备失败 | 否 | 红色短文本；不提供元信息条操作 |
| 提示 | 主题色或琥珀色 | 缺少作者、缺少原始发布时间但系统已补默认值、已清理营销内容 | 是 | 说明已自动处理的结果；允许直接确认，也允许编辑修正 |
| 正常 | 默认中性色 / 成功色 | 信息完整、准备完成、可导入 | 是 | 只显示来源和“可导入” |

颜色只做辅助，状态文字必须直接说明结果，避免只靠颜色传达“不能导入”。同一条元信息同时存在多个状态时，按“阻断 > 提示 > 正常”显示；来源文本保留在另一侧，不另外占一块卡片。

建议的单行文案：

```text
晨间散步.md                         未识别作者，已自动处理
https://mp.weixin.qq.com/s/abcdef…     读取失败
旧文章.md                             重复，已跳过
周末阅读.md                            已清理营销内容
```

### 4.6 作者和时间缺失时的导入规则

缺少作者或缺少原始发布时间属于**可自动补全的提示**，不再作为阻断错误：

- 缺少作者时，系统沿用现有默认作者“轻读手记”；元信息条只提示“未识别作者，已自动处理”。用户仍可在现有编辑入口改成真实作者。这个默认值可以后续做成内容池级可配置值。
- 缺少或无法解析原始发布时间时，确认导入的瞬间写入当前时间作为发布时间，按后台统一的北京时间显示；元信息条只提示“未识别时间，已自动处理”。这里的时间是实际确认保存时间，不是文件读取时间、任务创建时间或 URL 抓取开始时间。
- 两项都缺失时合并为“未识别作者，已自动处理；未识别时间，已自动处理”，不重复占用元信息条高度。
- 自动补全后的值参与后续保存和去重；用户在确认前修改后，以修改值为准。

文件读取失败、URL 抓取失败和规范 URL / 正文重复仍是红色阻断状态，不能因为存在默认值而进入确认范围。

当前代码里已经存在“轻读手记”这个作者兜底：普通文章编辑、单条保存，以及 URL / MD 批量导入都会在作者为空时写入该默认值。阅读预览里的“未署名”仍只是空作者时的显示兜底，不会覆盖已填写的作者。

两种批量导入在准备阶段记录缺失作者 / 时间的提示；缺少作者使用“轻读手记”，缺少或无效时间使用实际准备 / 确认时的当前时间。两者都不会阻止导入，用户仍可通过现有编辑入口修正。

### 4.7 文章营销信息的自动清理

先区分当前实现和目标方案：

- **链接导入当前会清理。** URL 抓取先把网页整理成语义段落，再执行头部引导、尾部推荐、点赞 / 关注 / 投稿合作等营销信息识别；高置信度内容会从正文移出，并保留“恢复”所需的原始内容和清理摘要。同批文章还会额外识别多篇重复出现的推广模板。
- **文档导入现在也会清理。** MD / Markdown / TXT 进入 `parseArticleDocument` 后，会按 Markdown 段落执行文章营销清理，再准备图片。清理模块保护代码块、表格、来源、署名和正文长度；Markdown 安全渲染仍负责过滤危险标签和协议，两者职责分开。
- **当前清理不是 AI 黑盒。** 它是基于语义段落、关键词组合、链接密度、图片形态和正文长度保护条件的确定性规则；判断不够可靠或清理后正文过短时，会放弃删除。

因此，没有把 URL 的整段 HTML 处理函数直接塞进文档入口。两种来源的格式不同，直接复用会让 Markdown 代码块、表格、链接和图片边界变得不稳定。当前已抽出 Markdown 侧的小型公共 `article-marketing-cleanup` 模块，并让两种入口使用一致的清理结果字段和恢复机制，保留来源适配层：

1. URL 适配层负责把网页 HTML 整理为语义段落。
2. MD / Markdown / TXT 适配层负责把 Markdown 解析为同样的正文段落，并保护代码块、表格、链接、图片和引用结构。
3. 清理模块只负责识别高置信度营销段落、保护 Markdown 结构，并返回清理后的正文、移除内容、恢复正文和清理摘要；URL 入口继续使用已经覆盖公众号 HTML 边界图片和尾部模板的成熟规则。

两种文章方式在准备图片前都按同一顺序执行：

```text
来源格式解析 → 营销信息识别与清理 → 图片准备 → 预览 → 判重 → 确认导入
```

统一后的产品行为：

- URL 和 MD 导入都可能出现同一条简短提示：`已清理营销内容`；没有清理时不显示多余提示。
- 提示只放在卡片上方的一行元信息条；“恢复”是唯一特例的蓝色纯文字操作，不增加查看、重试或其他操作。
- 现有文章的恢复机制继续沿用并集成到这条元信息中；点击后按现有机制切换为“重新清理”，MD 导入也保存同样的恢复数据，恢复入口和恢复结果保持一致。被清理的尾部图片仍按现有规则不恢复，只恢复文字。
- 清理后的正文才参与正文内容指纹，保证同一文章通过 URL 抓取和 MD 导入时不会因为一边带营销尾部、一边没有而产生不同判重结果。
- 只有高置信度内容才自动删除；作者 / 编辑署名、来源、免责声明、版权和风险提示继续受保护。无法确认时保留原文，让运营通过现有编辑入口处理。

这样做的重点是**复用一套清理结果格式和恢复机制**，而不是让两种来源共享同一个网页解析函数。Markdown 入口已落地 `article-marketing-cleanup` 模块，URL 入口继续保留经过验证的 HTML 清理适配器。

### 4.8 当前文章去重的真实逻辑

现在的服务端会在预览准备阶段和最终确认阶段都做判重，规则已经收敛为两个主要依据：

1. **规范来源 URL**：公众号 URL 会先规范化。微信文章优先使用 `__biz + mid + idx` 形成稳定身份，忽略分享追踪参数；其他 URL 会去掉常见追踪参数并排序查询参数。
2. **正文内容指纹**：只对正文可读文本做统一规范化后计算指纹，不把标题、作者、封面和导入时间混进来。

历史文章已有的 `sourceHash`、`importFingerprint` 等字段仍保留在记录中；其中 `sourceHash` 只用于旧 URL 记录兼容，新的判重不再使用旧的综合导入指纹，也不再维护“同来源有修改”“疑似重复”或标题 / 作者相似等额外分支。

### 4.9 两个判重依据的落地规则

文章统一后使用两个依据：

1. **规范来源 URL**：规范化后的 URL / 微信文章身份相同，判定为重复。
2. **正文内容指纹**：对正文的可读内容做统一规范化后计算指纹，相同就判定为重复。指纹只看正文，不把标题、作者、封面和导入时间混进来。

统一规则变成：**同一规范 URL，或正文内容指纹相同，即为重复；两者都不同，才是新文章。** 同批文章和目标内容池都使用同一规则，预览阶段检查一次，最终保存时再检查一次。

这个规则能覆盖主要场景：

| 场景 | 结果 |
| --- | --- |
| 同一文章 URL 只更换分享参数 | 规范 URL 相同，重复 |
| URL 不同但正文完全相同 | 正文指纹相同，重复 |
| MD 没有原文 URL，但正文与已有文章相同 | 正文指纹相同，重复 |
| 同一 URL 的正文被修改 | URL 相同，仍判重复，不自动覆盖 |
| 标题、作者或封面不同，但正文不同 | 不因标题 / 作者 / 封面单独相同而判重 |

这样删除了“标题 / 作者疑似重复 + 同来源有修改”的分层判断。不同公众号发布完全相同正文时，也会按正文重复处理；当前项目规模下直接跳过即可。

历史文章已有的 `sourceHash`、`importFingerprint` 等字段可以继续保留，作为旧数据和编辑兼容字段；新任务只计算规范 URL 和正文指纹，不需要重新迁移历史内容。作者默认值和导入时间也不进入正文指纹，因此自动补全不会让同一正文失去去重能力。

同一条元信息只需显示一条结果：`重复，已跳过`。不向运营解释内部哈希、旧字段、来源差异或正文差异。

## 5. 统一状态和表达逻辑

所有类型使用同一顺序和句式：

```text
导入预览
共 28 篇 · 可导入 26 · 需处理 1 · 重复 1 · 已导入 0
```

数量单位固定为：文案、音频、心笺用“条”；文章用“篇”；图册用“组”。位置和语法固定。为避免标题栏过长，数量为 0 的非关键状态可以隐藏；出现过该状态或需要解释时，在筛选项中仍可查看。

确认按钮统一使用对应单位：`确认导入全部 X 条`、`确认导入全部 X 篇`、`确认导入全部 X 组`。

右侧只保留一个主按钮，统一使用带数量的句式：

- 有可导入项：`确认导入全部 26 篇`。
- 正在读取 / 抓取 / 准备：`准备中…`，按钮禁用。
- 网络或上传中断且可以续作：`继续导入全部 26 篇`。
- 没有可导入项：按钮禁用或隐藏，并在摘要下显示原因。
- 已完成：`本批已完成`，按钮禁用。

这样“X 条可导入”不再作为与按钮并列的另一种主表达；数量只在摘要和主按钮中出现一次明确含义。确认范围始终是本批全部可导入项，包含其他分页和当前筛选未显示的项目。

### 5.1 单条预览卡片

对于后续四种内容，统一时可以复用同一套卡片外元信息条。文章导入本轮不调整现有阅读卡片内部结构：

- 文章阅读卡片的标题、正文、排版保持当前样式。
- 文章卡片右上角现有编辑、删除、重新抓取按钮保持当前位置和机制。
- 来源和重复 / 需处理提示放在卡片外、紧贴卡片上方的一行元信息条。

内容不同只替换预览主体：文案和心笺显示文本，音频显示文件名及时长，图册显示缩略图，文章显示阅读卡片。统一的元信息条位置和状态表达不随内容类型移动。

### 5.2 状态定义

界面统一使用以下用户语言，后台可以继续保留现有内部状态名：

| 用户看到的状态 | 含义 | 是否计入“可导入” | 主要操作 |
| --- | --- | --- | --- |
| 待准备 | 已读取来源，等待处理 | 否 | 等待 |
| 准备中 | 正在解析、抓取、上传或生成预览 | 否 | 等待 / 重试查询 |
| 可导入 | 已通过当前类型的校验和准备 | 是 | 编辑、移除 |
| 需处理 | 缺少正文、格式、图片或其他阻断问题未解决 | 否 | 编辑、重试、替换、移除 |
| 提示 | 作者 / 原始时间缺失已自动补全，或营销内容已自动清理 | 是 | 编辑修正或直接确认 |
| 重复 | 已判定不会新增 | 否 | 不提供元信息条操作；沿用现有卡片的移除操作 |
| 已导入 | 已写入目标内容池 | 否 | 查看结果 |
| 已移除 | 运营从本批次移除 | 否 | 不再参与确认 |

对不参与内容级去重的音频和图册，不显示虚假的“重复”状态；可以继续显示素材“已复用 X 张图片”等准备结果，但它属于素材处理提示，不属于内容重复。

### 5.3 重复提示

文章重复信息统一放在对应预览卡片上方的元信息条，使用图 2 的米色视觉语气，但保持一行高度。后续四种内容迁移时也沿用这个位置和句式：

- 所有重复：`重复，已跳过`

当前文案和心笺在预览前直接移除重复项，建议改为保留一张“重复”状态卡片并从可导入数量中排除。这样不会改变自动跳过结果，却能让用户知道哪一项被跳过，也能与两种文章导入使用相同的重复表达。

### 5.4 错误、进度和完成反馈

- **卡片内**：展示影响单条内容的具体原因，例如“缺少作者”“图片超过 5MB”“音频上传失败”。
- **预览标题栏**：展示批次数量和当前阶段，例如“准备中 12/28”。
- **标题栏下方**：展示会阻止整批操作的错误，例如批次超过 200 条、目标内容池失效、查询失败。
- **Toast**：只用于动作结果，例如“已导入 26 篇文章，跳过重复 1 篇”；不承载用户必须长期查看的状态。

图 1 的黑色“已导入 26 篇”应保留为完成 Toast，但同时在预览标题栏留下稳定的“已导入 26”结果；重复、失败和需处理信息不能只放在 Toast 中。

## 6. 其他四种内容的后续统一

文章统一完成后，再处理以下四种内容。它们复用文章的标题栏、卡片外元信息条、确认按钮和反馈层级。

### 文案手记 / 心笺

保留 TXT 分段和正文去重。预览中每段作为一张文本卡片；重复段落在卡片外元信息条显示“重复”并自动排除，解析失败的文件显示文件相对路径。确认按钮使用“确认导入全部 X 条”。

### 音频手记

保留每文件一条、50MB 限制、时长读取、响度标准化和失败重试。预览中显示文件名、大小、时长和上传状态。确认按钮使用“确认导入全部 X 条”。不显示内容重复状态。

### 图册手记

保留子目录 / 文件名分组和每组最多 9 张。预览中显示组名、缩略图和异常图片操作。图片素材复用显示在批次结果中，不转换为内容重复卡片。确认按钮使用“确认导入全部 X 组”。

## 8. 落地记录与后续顺序

本轮已经完成文章两种导入方式的第一阶段统一：

1. URL 抓取和 MD / Markdown / TXT 文件导入共用摘要顺序、文章单位和“确认导入全部 X 篇”按钮。
2. 两种方式都在阅读预览卡片上方使用一行元信息条；URL 直接显示链接，文档只显示文件名。
3. 重复、读取失败、抓取失败和图片准备失败在元信息条使用阻断色；作者 / 时间自动补全和营销清理使用提示色。
4. 两种方式都支持“恢复”蓝色纯文字操作，点击后切换为“重新清理”；文章卡片内部结构和编辑 / 删除 / 重新抓取工具保持不变。
5. 文章去重收敛为规范来源身份或正文内容指纹，历史字段继续兼容；移除疑似重复和保留为新文章的分支。
6. 文档导入接入营销内容清理、默认作者、默认时间和清理恢复接口，并补充代码块及已转存图片的验证。

下一阶段再以文章的元信息条、状态摘要和确认按钮为基准，迁移到文案、音频、图册和心笺；保留各自的解析、限制和媒体操作。

## 9. 验收口径

- 文章文件导入和 URL 导入进入预览后，摘要在同一位置，状态顺序一致，主按钮在同一位置且都带本批可导入数量。
- 文章两种方式都能在卡片和保存后的文章记录中看到统一的“原始来源”；URL 与 MD 的来源值按各自实际来源保存。
- 任意导入方式都能明确区分“总数、可导入、需处理、重复、已导入”；重复和失败不会只存在于临时 Toast。
- 同一批次确认范围不因分页、筛选或来源方式改变，按钮文案与实际提交范围一致。
- 文章 URL 与文章文件的重复提示位置和句式一致；规范 URL 或正文指纹相同就自动跳过，不再额外维护“疑似重复”分支。
- 元信息条按优先级显示颜色：重复 / 读取失败 / 抓取失败为红色阻断，作者 / 时间缺失并自动补全为主题色提示。
- 自动清理营销内容时，元信息条显示主题色状态和唯一的“恢复”蓝色纯文字操作；未发生清理时不显示该操作，其他状态也不显示操作。
- 缺少作者时使用现有默认作者“轻读手记”；缺少或无效原始时间时使用确认导入时间；两者都不阻止导入。
- 判重结果统一显示“重复，已跳过”，最终仍由服务端再次校验。
- 文案、心笺、音频、图册完成迁移后，沿用同一状态和按钮规则；其中音频和图册不因界面统一而新增内容级去重。
- 音频和图册的图片 / 音频复用仍显示为素材处理结果。
- 不改变各类型现有解析、限制、图片 / 音频处理、文章营销识别规则、草稿恢复和服务端幂等行为；只把同一套文章清理流程覆盖到文件导入并统一结果保存。

# 轻读手记小程序端 PRD

版本：v1.6（2026-09-13 实现核对）
适用范围：微信小程序用户端
关键约束：以当前 `miniprogram/` 正式源码和本目录设计规范为基准；原型不再维护。本文记录源码行为与产品边界，不表示生产环境配置或微信审核状态已经核验。

## 1. 产品概述

轻读手记第一版定位为“按日分发运营方手记、音频与图册，并承载长文章阅读的小程序”。核心体验是用户通过首页阅读手记、打卡，通过文章和心笺继续阅读，并使用收藏和分享等功能形成个人阅读记录。

本产品明确不是社群、后援会、直播间或公开互动广场，不提供粉丝榜、人气榜、广告观看榜、打榜任务、公开评论区和前台 AI 生成功能。

## 2. 用户角色

| 角色 | 说明 | 核心诉求 |
|---|---|---|
| 普通用户 | 通过分享或最近使用进入小程序 | 打开手记、浏览内容、打卡、收藏、留言 |
| 作者/运营者 | 内容和分享链路的发起者 | 持续分发内容、获得广告收益、查看用户反馈 |
| 开发者 | 根据 PRD 与当前设计规范维护小程序 | 明确页面、状态、接口和验收边界 |

## 3. 信息架构

底部 Tab 默认包含 4 项：

| Tab | 默认名称 | 是否可隐藏 | 说明 |
|---|---|---|---|
| 首页 | 首页 | 是 | 默认落地页，承载手记、打卡、数据和广告 |
| 文章 | 文章 | 是 | 文章列表与长文详情入口 |
| 心笺 | 心笺 | 是 | 暖心短句内容流 |
| 我的 | 我的 | 否 | 阅读记录、历史、收藏、留言、设置入口 |

规则：

- Tab 顺序固定为“首页｜文章｜心笺｜我的”；后台可按小程序配置文章、心笺的显示名称，首页和我的名称固定。
- 首页、文章、心笺可按小程序隐藏；我的始终显示。当前页面被隐藏时，前端跳转到按上述顺序排列的首个可见 Tab。
- 正常模式与临时提审模式切换时，后台界面预设首页显示状态；提审隐藏首页，正常显示首页。切换后运营可手动调整首页及其他 Tab 的显示状态，服务端不因模式字段强制覆盖；首页隐藏时继续按固定顺序进入首个可见 Tab。
- 冷启动和开发者工具重新加载时，前端必须先解析远端配置；远端不可用时读取本地缓存或内置值，并强制隐藏首页。首页已隐藏时不得先渲染首页业务内容再跳转，避免短暂闪现已隐藏页面。
- 当前已使用自定义 TabBar 支持动态隐藏 Tab。
- Tab 图标统一使用当前 `assets/icons/` 的同风格资源，`app.json` 中注册对应 PNG 默认态与选中态。文章使用原心笺的文档图标，心笺使用原日记的书本图标；两者的默认态和选中态必须成对替换，不得继续使用近似图标。
- 前端启动时读取当前小程序实例配置，并按 `contentPoolId` 使用内容池；分享标题模板统一读取全局 `shareSettings`。

### 3.1 字体规范

设计标注以 `375px` 视觉宽度换算，小程序在该宽度下 `2rpx = 1px`；实际随设备宽度适配，后台使用自己的桌面字号，不再要求与 Web 原型三端同步。基础阅读层级由 `caption`、`assist`、`control`、`body`、`section`、`title`、`hero` 七组 Token 组成；业务页面不得新增裸字号。

| Token | 小程序 | 375px 宽度换算值 | 使用范围 |
|---|---:|---:|---|
| `type-tab` | `22rpx` | `11px` | 底部 Tab 标签 |
| `type-caption` | `24rpx` | `12px` | 紧凑统计标签和单位、极短元信息 |
| `type-assist` | `26rpx` | `13px` | 首页统计标签和单位、时间、辅助说明 |
| `type-control` | `30rpx` | `15px` | 操作条、输入框、紧凑说明 |
| `type-body` | `32rpx` | `16px` | 正文和普通内容卡片 |
| `type-section` | `34rpx` | `17px` | 设置项、分区标题、标准主按钮 |
| `type-title` | `36rpx` | `18px` | 页面标题、内容标题、紧凑统计数值 |
| `type-metric` | `38rpx` | `19px` | 首页统计主数值 |
| `type-hero` | `44rpx` | `22px` | 沉浸式主标题 |

常用组件变体包括：底部 Tab `type-tab`、首页主统计 `type-metric`、手记引导 `type-prompt`（`34rpx / 17px`）、打卡成功 `type-success`（`40rpx / 20px`）和留言引用 `type-reference`。引用字号统一由 `calc(var(--type-body) - 2rpx)` 派生，不单独写死三档字号。图册、返回和设置箭头均使用 SVG 或图形样式，不作为文字字号管理。

二级页面顶部标题固定使用 `36rpx` 并以屏幕水平中线物理居中，不受右侧胶囊按钮影响；“我的”页头像占位字和昵称固定使用 `38rpx`，“设置”固定使用 `34rpx`。这些是导航与身份卡片的 UI 固定值，不改变基础 Token 契约，也不随 reading font mode 变化。

## 4. 页面需求

### 4.1 首页

首页默认文案：`给你的专属秘密`。

首页由 3 个主要功能盒子组成：

| 模块 | 优先级 | 功能 | 页面行为 |
|---|---:|---|---|
| 手记卡片 | P0 | 打开今日手记内容 | 在盒子内完成广告、加载、结果、换一个；留言功能开启时提供留言 |
| 打卡盒子 | P0 | 完成每日打卡 | 在盒子内完成广告、加载和成功态 |
| 数据盒子 | P1 | 展示用户阅读数据 | 展示今天第几位、连续打卡、累计阅读值 |

#### 4.1.1 打开手记流程

```text
进入首页
→ 点击打开手记
→ 若首页手记激励广告开启且未命中免广告次数，先按配置显示确认弹窗，再观看激励广告
→ 广告成功或命中免广告次数后，手记卡片内展示内容
→ 用户可点赞、收藏、转发分享；留言功能开启时可留言
→ 用户可点击“换一个”
```

规则：

- 手记未打开时，左侧展示“今日手记”标签和两行引导文案，右上角展示圆形“轻读手记 · Secret Box”邮戳，主按钮位于文案组下方。
- 引导文案由后台按当前小程序下发 `dailyContentPromptTexts`，前端进入首页时随机展示一条，并尽量避免与上一次连续重复。
- 每条引导文案按第一个中文逗号 `，` 拆成两行，逗号保留在第一行；逗号前后字数不限定。
- 接口失败、配置为空或不合法时，使用内置两条提示语“想说的，都悄悄放这里了”“打开前，猜猜里面是什么”，优先避免连续重复；不再使用旧的单条兜底。
- 引导文案只负责营造打开前的好奇感，不说明手记内是文案还是图片。
- 手记结果只能是“手记”“音频”或“图册”之一，不允许同一结果混合多个内容类型。
- 音频使用简易播放器展示，默认不自动播放，用户主动点击后才开始播放；播放器支持播放、暂停、进度展示和拖动定位。
- 音频展示标题优先取后台保存的标题；新上传音频的初始标题默认取原始文件名移除最后一个扩展名。运营可在后台单独修改标题，不影响原始文件名。标题溢出时在播放器标题区域循环滚动展示。
- 音频文件可以较长；正式小程序使用平台播放器能力，以支持已缓冲部分开始播放。具体是否支持边下边播取决于音频格式、COS 响应头与微信客户端能力，不能以一次性完整下载作为前置条件。
- 后台运营上传的音频完成上传后即可参与投放；是否向当前小程序下发，由 `dailyContentTypes.audioEnabled` 控制。
- 当前小程序实例通过 `dailyContentTypes.imageEnabled` 和 `dailyContentTypes.audioEnabled` 分别控制图册、音频。服务端随机抽取时必须排除已关闭类型；两个开关均关闭时，仅下发文字手记。
- 随机抽取必须由服务端按滚动 30 天排除当前用户在当前数据范围内成功打开过的手记内容；其他用户的打开记录不影响抽取。`共享数据`模式下，同一账号在同一内容池的共享小程序共用这份记录；`独立数据`模式下，只使用当前小程序和当前内容池的记录。首页打开、首页分享链接只携带 `type` 的打开、分享内容失效后的“随机打开”和“换一个”都属于随机抽取，均受此规则约束；“换一个”还应额外排除当前正在展示的内容。候选内容耗尽时不得回退抽取最近 30 天内已打开的内容，直接提示“暂无可打开内容”，不播放广告且不计次。
- 首页分享时，小程序从文案、音频、图册的固定顺序中，在当前启用的类型内轮换选择。每个页面实例从文案开始，每次调起分享即前进一次，用户取消微信发送也照常前进，关闭类型自动跳过；分享卡片的预热或渲染进度不得改变该选择。所选类型同时用于手记分享模板和分享链接，标题与封面均按该类型模板生成；链接只携带 `type`，不携带 `contentId`。接收者进入首页后，客户端通过 `POST /api/miniapp/daily-content/availability` 静默检查该类型是否可打开，不显示加载、弹窗或广告；检查尚未完成时，用户点击首页打开按钮才显示加载。正常时按既有广告和加载流程，仅在该类型内随机抽取内容。
- 已打开手记内分享时，手记分享模板使用当前内容类型，分享链接同时携带 `type` 和 `contentId`。接收者进入首页后静默检查该内容是否可打开；检查完成且内容正常时，点击首页打开按钮后按既有广告和加载流程展示该 `contentId` 对应的同一份内容。携带有效 `contentId` 的指定内容打开不受“近 30 天随机排除”限制，但仍须通过既有类型、启用状态和存在性校验。
- 分享链接指定的类型已关闭、该类型没有内容、指定内容被删除、不存在或与类型不符时，不得静默替换为其他类型或内容。在广告和计次前显示“内容暂时无法打开 / 可随机打开另一份”弹窗，按钮为“暂不”和“随机打开”。“暂不”关闭弹窗并停留在未打开首页；“随机打开”清除原分享约束，从当前启用且有内容的类型中随机打开另一份，并直接进入激励广告流程，不再显示第二次广告确认。没有可打开内容时，提示“暂时没有可打开的手记”，不播放广告且不计次。网络、服务、广告和每日次数上限错误继续使用原有提示，不触发此兜底。
- 通过任一分享链接打开手记，仍计入接收者当前数据范围的当日打开次数，并继续由服务端按“用户 + 当前数据范围 + 自然日”校验。
- 同一用户在当前数据范围内每天最多打开次数由当前小程序的后台配置决定，默认 5 次，范围 0 到 9 次；`0` 表示不限次数。共享模式下，同一内容池的共享小程序共同累计次数，当前发起操作的小程序配置决定本次校验使用的上限。
- 达到次数上限时，提示“今天没有更多消息，请明天再试”。
- 生产环境必须由服务端按“用户 + 当前数据范围 + 自然日”校验打开次数。
- 用户点击“换一个”时，不返回手记未打开态；服务端应排除当前内容后重新随机抽取。若手记激励广告已启用且已配置广告单元，弹窗提醒开启时先显示“完整观看广告 即可更换手记”，用户确认后进入广告并在完整观看后自动展示新内容。
- 手记内容成功出现后不再额外显示“手记已打开”提示，避免遮挡刚出现的内容。
- 留言采用客户端 fail-closed：只有配置明确返回 `messagesEnabled: true` 时，留言输入才在当前内容卡片内展开；字段缺失、配置请求失败或值为 false 时，隐藏首页、心笺、文章及“我的”页的留言入口和留言内容。`messagesEnabled` 是普通可编辑参数，模式字段不额外强制关闭或开启；提审与实际上线配置应按平台要求保持一致。
- 激励广告未完整观看时，只在当前页面展示约 3 秒轻提示，不跳转。手记默认提示为“完整观看广告后，即可打开手记”，打卡默认提示为“完整观看广告后，即可完成打卡”，文章默认提示为“完整观看广告后，即可展开全文”；后台配置存在时优先使用对应配置。
- 只有微信明确返回 `isEnded === true` 时才视为完整观看；用户中途关闭或结果缺失时不放行。
- 激励广告加载、展示或播放异常时，若当前广告位开启“无广告时视为看完”，则直接继续业务操作；关闭时固定提示“激励广告暂不可用，请稍后重试”。
- 打开手记或打卡的网络请求失败时，固定提示“网络不稳定，请检查网络”；未归类的服务异常固定提示“服务不可用，请稍后重试”。
- 当日手记次数达到上限时，提示“今天没有更多消息，请明天再试”；手记内容池为空时，提示“内容正在准备中，请稍后再来”；重复打卡时，提示“今天已经打过卡，请明天再试”。

#### 4.1.2 打卡流程

```text
进入首页
→ 点击立即打卡
→ 若首页打卡激励广告开启且未命中免广告次数，先按配置显示确认弹窗，再观看激励广告
→ 广告成功或命中免广告次数后，打卡盒子内展示成功态
→ 按服务端返回值增加阅读值，当前每次有效打卡增加 5 点
→ 展示 14 天打卡日历
```

- 打卡前主文案由后台按当前小程序下发 `checkinBeforeTexts`；打卡后的日历说明由 `checkinAfterTexts` 下发。
- 两组文案均在当前设备每天选定一条，同一天刷新页面不更换；次日优先避免与前一天重复。
- 两组配置为空或获取失败时，分别回退到内置打卡前文案池“今天也等到你了 / 每天都来打卡吧”和打卡后文案池“今日已点亮，明天再来打卡吧！ / 感谢你的支持，明天我等你哦！”，继续按设备与日期选取。
- “打卡支持”“打卡成功”、连续/累计次数属于固定状态信息，不作为运营文案配置。

打卡成功态结构：

1. 固定状态标题“打卡成功”。
2. 两行 14 天日历。
3. 后台配置的打卡后展示文案。

日历规则：

- 两行共 14 天。
- 第一行展示上一周周一到周日。
- 第二行展示本周周一到周日。
- 今天永远位于第二行，并按真实星期位置高亮。
- 已打卡历史日期使用低饱和浅色块。
- 今天使用主强调色。
- 未来日期不高亮。
- 打卡前展示“阅读值 +N”，`N` 由服务端下发，当前为 5；前端不得写死奖励数值。

#### 4.1.3 数据盒子

展示项从左到右固定为：

| 数据项 | 说明 | 配置 |
|---|---|---|
| 今天第几位 | 按当天完成打卡时间排序 | 后台可隐藏 |
| 已连续打卡 | 连续打卡天数 | 后台可隐藏 |
| 累计阅读值 | 用户阅读互动综合值 | 后台可隐藏 |

阅读值公式：

```text
阅读值 = 累计打卡次数 × 5 + 累计打开手记次数 × 3 + 当前有效点赞数 × 1 + 当前有效收藏数 × 1 + 有效留言数 × 1
```

规则：

- 总值下限为 0，上限为 100000，不执行每日衰减或凌晨结算。
- 打卡后立即刷新首页统计；打开手记、点赞、收藏和留言完成后也应刷新阅读值。
- 阅读值一万以下展示完整数字，一万以上用 `k` 缩写并加“点”后缀。
- 首页统计项按后台可见项数量重排：3 项三列、2 项两列、1 项单列；全部隐藏时不渲染统计区，不保留空白。
- 首页统计数值使用 `--type-metric`（普通/较大/最大为 `38/40/44rpx`）、字重 `650`、行高 `1.25`；标签与单位使用 `--type-home-stat-detail`（`28/30/34rpx`）、字重 `400`、行高 `1.4`。

### 4.2 心笺

顶部文案：`暖心的文案短句`。

内容类型：

- 晚安
- 早安
- 鼓励
- 治愈
- 阅读类短句

页面规则：

- 通过当前小程序配置 `system.lettersSortMode` 控制排序方式：`random` 为随机打乱，`sequence` 为按入库顺序倒序展示；默认值为 `random`。
- 卡片不显示日期。
- `random` 模式由服务端按当前小程序、内容池和用户分别维护顺序，不读取点赞、收藏、留言等互动数量作为排序权重。第 1 页请求会生成新顺序，用户主动下拉刷新会重新请求第 1 页并换一套顺序；第 2 页及后续分页沿用本次顺序。`sequence` 模式仍按入库顺序倒序返回。
- 从详情页或其他页面返回、Tab 切换、分享返回、点赞、收藏、留言均保留现有顺序，不主动重排；触底分页只追加数据，不重排已展示项。服务端列表会话在单个 Admin 进程内短暂保留，具体缓存边界见[内容列表随机与推荐顺序说明](TEC-content-randomization.md)。
- 通过分享进入心笺页时，客户端仅在当前页面会话内把分享链接 `contentId` 对应且已成功返回的心笺移到列表首位；不改变后台排序、不写入本地持久状态。普通页面回流和回到前台保持当前置顶状态；用户下拉刷新或页面重建时清除该临时状态，并按当前排序重新加载。若目标不存在、当前心笺页已隐藏或接口未返回该条内容，清楚提示“分享的内容暂时不可用”，不得以列表中的其他心笺替代目标；分页追加时按内容 ID 去重。
- 列表仅显示当前内容池数据；空池显示空状态，不注入原型演示卡片。
- 页面内按广告规则插入原生模板广告。

互动能力：

| 能力 | 规则 |
|---|---|
| 点赞 | 公开计数 |
| 收藏 | 可公开显示收藏数量，并在用户收藏后变色 |
| 留言 | 仅自己和作者可见 |
| 分享 | 走微信官方转发机制 |

### 4.3 文章

顶部文案默认：`走心的精选文章`。

文章列表规则：

- 通过当前小程序配置 `system.articlesSortMode` 控制排序方式：`random` 为随机打乱，`sequence` 为按入库顺序倒序展示；默认值为 `random`。展示标题和可选封面；没有封面时自动收敛为纯文字卡片，不保留空白图位。
- `random` 模式由服务端按当前小程序、内容池和用户分别维护顺序，不读取点赞、收藏、留言等互动数量作为排序权重。第 1 页请求会生成新顺序，用户主动下拉刷新会重新请求第 1 页并换一套顺序；第 2 页及后续分页沿用本次顺序。`sequence` 模式仍按入库顺序倒序返回。
- 从详情页或其他页面返回、Tab 切换、分享返回、点赞、收藏、留言均保留现有顺序，不主动重排；触底分页只追加数据，不重排已展示项。服务端列表会话在单个 Admin 进程内短暂保留，具体缓存边界见[内容列表随机与推荐顺序说明](TEC-content-randomization.md)。
- 当前小程序可统一选择三种列表布局：常规卡片、大图卡片、混搭模式。常规卡片使用左侧固定三行内容区（标题最多两行，底部固定作者与点赞/收藏数据）加右侧固定正方形封面，封面按中心区域裁切；大图卡片使用上封面下标题，通栏封面比例为 `2.35:1`；混搭模式按文章 ID 稳定散列，在常规卡片与大图卡片之间均衡轮换，同一文章刷新后不得随机跳版。
- 点击卡片进入独立文章详情页；列表加载、空状态和失败状态不得改变卡片宽度或推动 TabBar。
- 从任一文章详情返回文章列表后，客户端仅在当前页面会话内把当前文章置于列表首位；不改变后台排序、不写入本地持久状态。普通页面回流和回到前台保持当前置顶状态；用户下拉刷新或页面重建时清除该临时状态，并按当前排序重新加载。分享目标不存在、当前文章页已隐藏或详情接口拒绝访问时，清楚提示“分享的内容暂时不可用”，不得将其他文章视为分享目标；分页追加时按内容 ID 去重。

文章详情规则：

- 顶部依次展示标题和可选封面，正文使用经过服务端清洗并由客户端再次清洗的富文本；正文图片上下间距与段落一致，首尾不额外留白。
- 未解锁时只返回并展示预览正文，预览末尾使用渐隐和“展开全文”按钮；展开位置提供五个固定档位：最早 `10vh`、较早 `20vh`、适中 `30vh`、较后 `40vh`、最晚 `50vh`，默认“较早”，按钮文案由当前小程序统一配置。
- 展开全文可绑定激励广告。用户完整观看、命中当日免广告次数或按“无广告时视为看完”规则放行后，由服务端记录“用户 + 数据范围 + 文章 + 自然日”解锁；当天再次进入同一文章直接展示全文，不重复要求解锁，次日重新计算。
- 详情页从其他文章中随机返回“继续阅读”，最多 100 条，每次分页加载 20 条；可推荐文章不足 100 条时加载完现有内容自然结束。服务端统一维护推荐顺序并缓存 30 分钟，同一内容池中同一篇文章在缓存窗口内对所有用户保持一致；分页追加不得重复，列表项不得包含当前文章。推荐卡片复用文章列表的三种布局和封面收敛规则。
- 文章列表页提供文章原生模板广告和文章插屏广告；文章详情提供文章详情激励视频、文章详情插屏广告、文章详情开头原生模板广告，以及使用同一配置的正文中段、正文尾部和继续阅读列表原生模板广告。六个广告配置项分别为 `articlesNative`、`articlesInterstitial`、`articleExpandRewarded`、`articleInterstitial`、`articlesStartNative`、`articlesEndNative`；广告关闭、缺少 `adUnitId` 或加载失败时不得留下空白容器或遮挡正文。
- 分享使用文章标题、封面和携带 `contentId` 的详情路径；没有封面时使用安全默认图。
- 通过分享打开文章时直接进入对应文章详情，不得先展示文章列表或发生列表闪跳；目标不存在或不可访问时在详情页明确提示“分享的内容暂时不可用”。
- 任一文章详情点击左上角返回时，始终进入文章列表并保留本次返回文章的首位状态；无论首页是否启用，均不得回到首页或退出小程序。

文章详情底层契约：

- 页面身份只使用 `contentId`：列表和推荐项跳转 `/pages/article/article?contentId={contentId}`；客户端通过 `GET /api/miniapp/articles/{contentId}` 获取详情，接口要求有效的小程序会话并按当前小程序与数据范围读取文章。
- 文章列表接口只返回摘要和分页信息，不返回 `bodyMarkdown`、`bodyHtml` 等正文源数据；详情接口返回 `article`、首批 `recommendations`、`recommendationPagination`、`articleDisplay` 和 `unlockedToday`（分享配置单独由文案包下发），继续阅读后续页面通过详情推荐分页接口加载。`recommendationPagination` 至少包含当前页、每页数量、总量、总页数和供后续分页复用的随机种子；服务端在 30 分钟缓存窗口内统一使用该推荐顺序，并将总量限制为最多 100 条、每页最多 20 条。`article.previewHtml` 始终可用，未解锁时 `article.bodyHtml` 为空且 `article.bodySegments` 不渲染；已解锁时返回完整正文及可插入广告的分段。列表随机、推荐缓存和服务重启边界见[内容列表随机与推荐顺序说明](TEC-content-randomization.md)。
- 管理端保存的唯一正文源是 `bodyMarkdown`。服务端先规范化 Markdown、渲染为受控 HTML 并清洗危险标签、属性、链接协议和图片地址；小程序收到 `previewHtml`、`bodyHtml` 或分段后再次清洗，正文不直接信任接口 HTML。
- 预览由服务端从 Markdown 派生，按正文块累积约 320 个可见文字后停止，不修改原始 Markdown。客户端按 `articleDisplay.previewPreset` 将预览容器限制为 `10/20/30/40/50vh` 五档，默认 `20vh`；按钮文字来自同一配置。
- 展开全文使用 `POST /api/miniapp/articles/{contentId}/unlock`。客户端仅在激励广告完整观看、命中该广告位当日免广告次数，或配置允许“无广告时视为看完”时提交 `rewarded` 状态；服务端再次校验广告配置和次数，并将解锁按“用户 + 数据范围 + 文章 + 自然日”记录。当天重复进入同一文章直接返回全文；`hideFullArticle=false` 时服务端直接视为已解锁。
- 进入详情后单独调用 `POST /api/miniapp/articles/{contentId}/open` 记录打开行为，使用幂等键避免重复记账；点赞、收藏和留言均以 `source=article`、`sourceId=contentId` 绑定当前文章。
- 文章解锁后，只有当正文可分成至少两段、总可见文字不少于 800 字，且广告前后各有至少 320 字时，服务端才在段落边界插入一个 `middle-ad` 分段；否则保持一个完整 HTML 分段。客户端依据首尾媒体边界标记调整图片与广告相邻间距。
- 文章列表分页追加数据后，以合并列表的全局位置计算 `articlesNative` 原生广告插入点，默认首个位置为第 3 条、间隔 10 条；详情推荐列表分页追加后同样以合并推荐列表的全局位置计算广告插入点，沿用 `articlesEndNative` 广告位，首个位置以 `articlesNative.firstAfter` 为基准顺延 5 条，不得每页重新从首条计算。插屏广告仅在对应页面可见且空闲时调度，激励解锁期间暂停详情插屏。

### 4.4 我的

页面定位：弱化传统账户中心，强化阅读记录。

结构：

1. 顶部：头像、昵称、设置。
2. 中部：默认 1×4 统计入口；留言功能关闭时隐藏“我的留言”，剩余 3 项自动使用三列等宽布局铺满屏幕宽度。
3. 下部：最近打开的 100 个手记。

统计入口固定顺序：

| 入口 | 跳转 |
|---|---|
| 累计打开 | 累计打开列表 |
| 互动记录 | 互动内容列表 |
| 我的留言 | 留言列表 |
| 我的收藏 | 收藏列表 |

规则：

- 可见统计项均支持 `1.2k` 缩写；留言功能关闭时不渲染“我的留言”入口，剩余三项自动平均排列并占满屏幕宽度。
- 统计数值使用 `--type-title`（`36/40/44rpx`）；标签使用 `--type-mine-stat-label`（`26/28/30rpx`），单位使用 `--type-caption`（`24/26/28rpx`）；四项可见时使用四列，三项可见时使用三列等宽布局。
- 每项统计值均表示对应列表中的内容数，不表示打开、点赞、分享、留言或收藏的操作次数；同一内容在同一列表中只计 1 条。
- 互动定义为点赞、发起分享或成功留言，不包含收藏；互动记录覆盖手记文案、音频、图册、心笺和文章。已打开手记的分享按当前内容记录；未打开内容时的首页类型轮换分享不对应具体内容，不写入互动记录。
- 互动记录按内容去重，同一内容发生多次或多种互动仍只计为 1 条；列表左上角不显示内容类型，直接沿用原内容类型标签样式显示“点赞过”“分享过”“留言过”，同一内容的多个互动标签在同一行并排展示，并按最近一次互动时间倒序排列。
- 用户取消点赞后仍保留“点赞过”的历史记录；分享按用户调起微信分享面板记录，不宣称分享已经成功送达。
- 留言功能开启时，“我的留言”列表覆盖当前支持留言的手记、音频、图册、心笺和文章；关闭时隐藏该入口。
- 留言按 200 个计数单位限制，ASCII 字符计 1、其他 Unicode 字符计 2，界面提示“最多可输入 100 个中文字符”；前端截断与服务端校验使用同一规则。
- 同一用户在同一内容上仅保留当前一条留言，再次提交覆盖原留言并更新 `updatedAt`。
- “我的留言”列表以留言正文为卡片主体；正文默认最多展示两行，超过两行时支持点击展开和收起，展开状态仅作用于当前卡片。
- 留言正文下方展示被留言内容的引用卡。文字、文章、音频、图册分别使用 `message-reference-text`、`message-reference-article`、`message-reference-audio`、`message-reference-album` 四个专用组件，统一浅色背景、内边距、圆角和左侧细边，页面只负责选择内容类型。文字引用也必须由完整的引用卡外壳包住，截断只作用于内层文字，不得裁切卡片内边距或露出第三行。
- 手记、文本和心笺引用显示正文开头，最多两行，超出显示省略号，不提供展开按钮；文章引用显示左侧最多两行的标题和右侧正方形封面，保持顶部对齐；音频引用显示单行标题、当前播放时间、进度条与播放/暂停按钮，复用历史列表播放逻辑；图册引用按可用宽度约显示 4.5 张正方形缩略图，可横向滑动并点击预览。音频不另加“引用音频”或时长摘要，图册不另加图片数量说明。缺少对应字段时使用可用标题或安全默认文案，不隐藏整条留言卡片。
- 引用正文、文章标题和音频标题共用 `--type-reference: calc(var(--type-body) - 2rpx)`，始终比当前正常内容文字小 `2rpx`：普通 `30rpx`、较大 `34rpx`、最大 `38rpx`。颜色、字重和字距沿用正常记录列表的内容文字规则；封面、播放按钮和图册缩略图不随字号档位额外缩放。
- 留言框右上角提供直接删除，不弹确认；删除后我的留言列表、阅读值和互动记录同步更新：该内容还有点赞或分享时保留对应标签，只有留言时该互动记录消失；独立的点赞、收藏和分享状态与公开计数保留。
- 离线删除先在本地生效，网络恢复后同步服务端；同步完成前后均不得恢复已删除的旧留言。
- 我的收藏列表覆盖手记、图册、音频、心笺和文章。
- 点击头像或昵称进入「个人资料」页。
- 「我的」页展示最近打开的 100 个手记，完整记录从「累计打开」进入。
- 互动记录、累计打开、我的留言和我的收藏均复用「我的」广告配置，允许按统一规则插入原生模板广告和展示插屏广告。
- 互动记录、累计打开、我的留言和我的收藏的列表时间只显示时间信息，不追加“互动”“打开”“留言”“收藏”等动作词。
- 最近打开与累计打开为空时统一显示“还没有记录 / 你打开过的手记会出现在这里”。

列表字段：

| 列表 | 字段 |
|---|---|
| 最近打开 | 最近 100 条记录的打开日期、内容类型和摘要；图册在有可用图片时显示一行横向缩略图条，按可用宽度约显示 4.5 张正方形缩略图，可左右滑动，点击任一缩略图可从该组图片的当前位置预览；音频显示文件名标题、当前播放时间、进度条与播放/暂停按钮 |
| 互动记录 | 最近互动日期、互动类型标签、内容摘要；手记文案显示正文，图册与音频复用我的收藏中的缩略图预览和播放器，文章保留封面和标题 |
| 我的收藏 | 收藏日期、内容来源；图册在有可用图片时显示一行横向缩略图条，按可用宽度约显示 4.5 张正方形缩略图并可左右滑动，缺少图片时显示“图片加载失败，点击重试”；音频显示标题、当前播放时间、进度条与播放/暂停按钮；文章显示封面和标题；手记、心笺显示文案摘要 |
| 我的留言 | 留言日期、内容来源标签、留言正文、被留言内容引用卡 |

“我的”及二级记录列表的字号适配：

- 适用范围为“我的”最近打开、累计打开、互动记录、我的收藏和我的留言（包含引用卡）。以“较大”档为视觉基准，普通、最大仅调整必要的文字行高，不改变文章页和心笺页的排版。
- 正常记录列表的文章标题、音频标题和文字摘要共用当前 `--type-body`（普通 `32rpx`、较大 `36rpx`、最大 `40rpx`），颜色为 `--color-text-secondary`，字重 `400`，字距一致。文章与音频标题仅按下表采用紧凑行高；正文摘要保持现有内容行高及展开行为。
- 正常记录文章封面固定 `112rpx × 112rpx`，引用文章封面固定 `104rpx × 104rpx`，标题始终顶部对齐。引用文章标题复用正常记录文章行高，不另设引用专用行高；引用字号仍为当前正文减 `2rpx`。
- 正常列表和引用音频播放按钮均固定 `80rpx`；左侧标题、时间和进度条所在区域自然撑满按钮所在行，进度条底边与播放按钮底边对齐，不按字号硬编码内容区域高度。图册尺寸继续按容器宽度计算。
- 累计打开、互动记录、我的收藏、我的留言统一使用二级记录列表的底部留白和设备安全区，页面背景覆盖至安全区底部。`expandable-text` 的隐藏全文测量内容不得扩大页面滚动范围或造成底部白色空白，正常两行折叠及展开/收起行为保留；在共享组件中处理测量内容的溢出，不添加单页固定高度补丁。

| 文字位置 | 普通行高 | 较大行高（基准） | 最大行高 |
|---|---:|---:|---:|
| 正常记录及引用文章标题 | `1.7` | `1.5` | `1.35` |
| 正常记录及引用音频标题 | `1.5` | `1.5` | `1.4` |

两行引用随字号自然排版，不用固定高度、整体 `scale` / `zoom` 或运行时高度测量实现缩小。三档均须在开发者工具中检查完整两行与省略号、文字卡外壳、标题与封面的顶部关系、音频进度条与按钮的底边对齐，以及二级列表末尾的背景、留白、安全区和实际滚动范围；展开、收起及切换字号后，隐藏测量内容均不得产生额外滚动。

### 4.5 设置与个人资料

设置页规则：

- 顶部第一个独立分区固定为「个人资料」。
- 隐私政策入口直接调用微信官方 `wx.openPrivacyContract` 展示公众平台配置的正式指引；用户协议在小程序内独立展示。
- 注销账号作为设置项，使用标准按钮样式。
- 点击后提示用户将注销申请发送至当前小程序在 Admin 配置的开发者邮箱，并注明需要注销的小程序名称和对应的账号信息；开发者核实后在 Admin 手动注销当前小程序账号。
- 不提供单独“意见反馈”入口。

个人资料页结构：

```text
头像（选择头像）
昵称（填写昵称）
手机号（快速授权）
→ 底部保存按钮
```

规则：

- 页面标题固定为「个人资料」。
- 头像使用微信官方头像选择能力。
- 昵称使用微信官方昵称填写能力。
- 手机号仅使用微信官方手机号授权能力获取。
- 官方接口返回的头像、昵称、手机号可自动保存。
- 用户手动修改昵称时，必须点击「保存」后提交。
- 手机号授权前置文案统一使用“手机号快捷登录”或“快速授权”，不得出现“微信”字样、微信 Logo 或仿官方授权样式。

## 5. 手记内容模型

### 5.1 手记

| 字段 | 规则 |
|---|---|
| 内容长度 | 必须非空；当前保存接口未强制 100 字上限，100 字以内属于编辑建议 |
| 推荐长度 | 30 到 60 字 |
| 包装文案 | 留言、短评、阅读感受、今日摘录 |

### 5.2 图册

| 字段 | 规则 |
|---|---|
| 图片数量 | 1 到 9 张 |
| 容器比例 | 3:4 竖图（宽 3、高 4） |
| 首页图册卡片 | `medium` |
| “我的”与打开记录缩略图 | `thumb` |
| 点击预览 | 优先 `medium` |
| 切换按钮 | 标准 SVG 图标，半透明、低存在感 |

限制：

- 文案和图片不会同时出现在同一个手记中。
- 页面文案保持中性阅读语气，不表达匹配、交友、唯一或排他关系。
- 图册和打开记录中的图册缩略图都可进入微信原生图片预览。每次进入预览优先确认点中的中图，可用后立即打开，不等待整组；相邻图在后台静默预取，其余图片交由原生预览按需加载。保留原生缩放、左右滑动和长按保存，不增加自定义全屏页或原图入口；长按保存的是当前预览版本。首页图册卡片另提供“保存原图”，点击后先确认，再按图册顺序批量保存原图到相册。点中图全部版本不可用才提示暂时无法查看。图片版本选择、超时与并发保护见 [《图片资产与封面处理规范》](./PRD-图片资产与封面处理规范.md)。

### 5.3 音频

| 字段 | 规则 |
|---|---|
| 格式 | MP3、M4A |
| 标题 | 优先取后台保存的标题；新上传音频默认用原始文件名移除最后一个扩展名生成初始标题 |
| 播放地址 | 后台返回可直接访问的 HTTPS `audioUrl` |
| 时长 | 后台保存 `durationSeconds`；播放器加载媒体元数据后以实际值校正 |

规则：

- 首页手记播放器默认不自动播放，支持播放、暂停、重播和进度定位；标题仅在溢出时滚动。
- 「我的」「累计打开」使用紧凑音频卡片：左侧为标题、当前时间和进度条，右侧为播放/暂停按钮；不在列表重复显示总时长。
- 同一页面同时只允许播放一条音频；切换到另一条时暂停上一条，返回原条时从已显示进度继续。页面退到后台或离开时暂停播放。
- 音频打开记录必须包含 `title`、`originalFilename`、`audioUrl` 和 `durationSeconds`，以便用户之后仍能按打开时的标题播放。旧记录缺少字段时，服务端可从当前内容池按内容 ID 回填；内容已不存在时展示不可播放状态，不伪造播放进度。
- 小程序直接将 `audioUrl` 交给 `InnerAudioContext`，不先完整下载文件。长音频是否可边缓冲边播放取决于微信客户端、音频格式和 COS 响应；上线前必须用真实 COS 音频在真机验证。

## 6. 分享需求

分享发起入口：

- 页面内分享按钮。
- 微信右上角胶囊菜单“转发给朋友”仅用于首页和文章详情；文章列表、心笺列表和“我的”隐藏页面级分享菜单。心笺仍仅通过每条内容卡片内的分享按钮发起分享。

规则：

- 分享分为手记分享和公开内容两类。首页和已打开手记内发起的分享均使用对应类型的手记分享模板：文案、语音、图片；文章和心笺复用“文案”类型的封面样式与封面文案，标题仍取公开内容自身，两者不绑定。
- 轻读手记的链接参数、首页类型轮换、静默可用性检查、同一内容展示、异常后的“随机打开”选择及计次规则，以“4.1.1 打开手记流程”为唯一标准；本章节不重复这些运行规则。
- 手记分享图固定为 `5:4` 的“底图 + 当日中文日期 + 封面文案”。文案和音频使用通用底图；图册使用当前图册第一张图片作为底图，无图片时按通用底图回退。日期格式为 `7月28日`，不使用英文星期缩写；封面文案限 4 至 20 个字，固定大字号，每行最多 10 个字，超过时自动分成两行；不使用首页手记邮戳，也不能显示任何正文或语音内容。
- 手记封面在小程序本地画布中使用后台启用的内置排版：居中对称式、左对齐大标题式。标题、封面文案和底图分别避开本设备近期重复，避免频繁分享时产生完全相同的卡片。
- 心笺分享标题固定按“第一句 → 第一段 → 前 50 字”提取，不读取后台标题库；文章优先使用自身标题（最多 50 字）。两者均套用文案类型的日期、封面文案、遮罩和排版样式。
- 公开内容有图片时使用内容自身图片：文章只使用 `coverImage`，绝不使用正文配图；当前心笺只有文案，因此始终优先使用后台下发的通用底图，未配置时才使用内置底图。公开封面统一叠加文案类型的日期、封面文案和手记排版。
- 图片派生规格、卡片版本选择、固定比例容器适配、分享画布、低分辨率行为和失败回退，以 [《图片资产与封面处理规范》](./PRD-图片资产与封面处理规范.md) 为唯一标准。
- 公开分享路径携带内容 ID，接收者进入后优先看到对应内容。不开通“分享到朋友圈”。
- 冷启动和热启动收到首页手记分享路径时，客户端都只将链接中的 `type`（及可选 `contentId`）作为首页待打开约束，并路由至首页；文章和心笺分享继续按各自的公开内容路径处理，不得将首页的类型分享路由到文章或心笺页。

客户端合成约束：

- 小程序进入首页、心笺或文章详情后，在不阻塞页面阅读的前提下预生成当前可分享卡片；同一画布一次只渲染一张，避免多张大图抢占内存。
- 分享图片来源的版本选择和失败回退遵循 [《图片资产与封面处理规范》](./PRD-图片资产与封面处理规范.md)；本地最多保存 12 张最近生成的成品图，规则版本、内容类型、底图、文案、排版或日期变化时自动生成新图。
- 手记封面的遮罩、颜色、日期与文案字号、分割间距、分割线长度和内置排版纵向微调均读取后台下发的受限参数：整体暗化遮罩为 `0` 到 `0.4`，文字保护遮罩为 `0` 到 `0.65`；日期字号、文案字号、分割间距、分割线长度均为 `20` 到 `100`，默认 `60`。分割间距统一控制日期、短分割线与文案各行之间的视觉节奏。封面文案超过 10 个字时，其折行行高自动在设备端按“文案字号 + 分割间距 × 25%，四舍五入”计算；默认字号和分割间距均为 `60` 时，行高为 `75`，不额外接受后台下发。规则版本变化后自动重绘并不再复用旧缓存。小程序只接受已定义的参数范围和两套内置排版，不下载或执行远程 CSS、WXML 或 JavaScript。
- 手记封面默认对所有底图加 20% 整体暗化遮罩，只读取文字预定区域的底图像素并判断明暗与复杂度：明暗稳定的浅色区域使用浅色底图文字色；深色或杂乱区域使用深色/杂乱底图文字色和文字保护遮罩。不会分析正文或整张图片，也不要求管理员为每张底图打标签。
- 若预生成失败，手记内容只可回退到不含内容的安全底图；公开内容可回退到当前公开图片或默认底图，不能因此等待服务端制图。
- 上线前必须将 COS 图片 HTTPS 域名配置到微信公众平台的小程序合法下载域名，并在真机验证 `wx.getImageInfo`、画布导出和微信好友分享；COS 图片不可使用需要登录或临时鉴权的地址。

## 7. 登录与跨小程序同步

统一用户方案：

- 服务端生成统一 `accountId`。
- 优先通过 `unionid` 归并用户。
- 异主体或无法绑定开放平台的小程序通过手机号兜底。
- `openid` 只用于单个小程序内识别，不作为跨小程序统一主键。

首次进入流程：

```text
进入小程序
→ 浏览不需要个人信息权限的基础内容
→ 使用头像、昵称、手机号等隐私能力时，由微信官方隐私授权弹窗展示《小程序用户隐私保护指引》
→ 用户同意后继续调用对应隐私能力；拒绝后仍可浏览基础内容
→ 用户可在个人资料中按需授权手机号、选择头像或填写昵称
→ 服务端建立或归并 accountId
```

规则：

- 拒绝手机号授权不影响基本浏览和当次操作。
- 未授权手机号且拿不到 `unionid` 的用户，只保留单小程序数据。
- 用户后续可在「设置 - 个人资料」补充授权。
- 当前小程序使用后台配置的用户数据模式：`共享数据`按账号和内容池同步，`独立数据`按账号、小程序和内容池隔离。
- 同一账号进入绑定相同内容池、且均使用`共享数据`模式的小程序时，昵称、头像、个人偏好、打卡、打开记录、点赞、收藏、分享、留言、阅读值、个人列表和个人统计保持连续。
- `独立数据`模式不读取或改写同内容池的共享数据，也不读取其他小程序的独立数据。
- 小程序切换内容池后只展示新内容池对应的数据，不跨池迁移；切回原内容池时恢复原数据。
- 后台切换用户数据模式时，前台继续使用旧模式直到迁移完整成功；失败时保持原数据和原模式，用户不能看到半迁移状态。
- 模式切换成功后，服务端立即以新数据范围为准。仍停留在前台的旧页面可能短暂保留旧缓存画面；小程序下次触发 `onShow` 时必须刷新数据范围，发现变化后清除旧范围缓存并重新进入当前页面。
- 微信小程序版本更新不会自动清空 `wx` storage。当前版本使用新的缓存命名空间隔离旧昵称、旧打开历史和旧业务缓存；升级后不得读取旧命名空间，也不得依赖用户手工清缓存完成迁移。
- 若用户在刷新前发起写操作，服务端必须以 `409 DATA_SCOPE_CHANGED` 拒绝旧范围请求且不产生任何业务副作用。客户端不得自动重放该操作，应更新数据范围、清除旧范围缓存并重新进入当前页面，提示“数据已更新，请重试”，由用户手动重试。
- 登录时同步一次，关键行为发生时实时同步一次。
- 离线时本地保留必要数据和行为发生时的数据范围，网络恢复后异步同步服务端，不得写入已经切换的新内容池或新模式。数据范围变化后，旧范围尚未同步的留言、删除和互动队列直接作废并清除，不迁移到新范围，也不自动重放。

关键行为包括：

- 打卡。
- 打开手记。
- 点赞。
- 收藏。
- 发起分享。
- 留言。

## 8. 广告

### 8.1 广告类型

第一版仅支持：

- 激励广告。
- 插屏广告。
- 原生模板广告。

不接入：

- 视频广告。
- 支付订单详情页广告。

广告规则：

- 首页手记激励广告、首页打卡激励广告均可独立开关。
- 文章展开全文激励广告独立开关，并与首页两类激励行为分别计数。
- 激励广告支持每天前 X 次免广告。
- 每个激励广告位独立配置“激励广告弹窗提醒”和“无广告时视为看完”，两项默认开启。
- 免广告计数维度为“用户 + 小程序 + 自然日 + 激励行为类型”。
- 插屏广告按广告位配置首次延迟 `delaySeconds` 与循环间隔 `repeatSeconds`。循环间隔为 `0` 时，同一运行生命周期内同一广告位成功展示最多一次；大于 `0` 时可循环，值限制在 `0–300` 秒。
- 用户关闭插屏后，循环位按配置间隔重新等待，非循环位不再展示；离开或暂停页面时清理当前调度。
- 插屏满足后台的首次延迟或循环间隔后，还须页面连续空闲 1 秒才可展示；用户重新操作时重新计时。
- 页面加载、刷新或列表加载中，或正在打开手记、打卡、播放/确认激励广告、输入或提交留言、授权、点赞收藏时，不展示插屏。页面有任何弹窗或授权弹层时同样不展示。
- 用户发起分享或打开图片预览后，当前页插屏暂停；回到页面后重新按上述条件判断。
- 原生模板广告通过页面内容流展示，不悬浮遮挡主流程。

当前版本不提供订阅消息。已设计的订阅页面和授权代码仅保留在源码中，所有入口默认隐藏；恢复条件见《已知暂缓事项》。

## 9. 图片加载与性能

图片处理规格、页面版本选择和失败回退以 [《图片资产与封面处理规范》](./PRD-图片资产与封面处理规范.md) 为唯一标准。前端性能要求：

- 列表和卡片按场景请求小图或中图，不将原图作为常规预加载资源。
- 图片进入视口附近时再加载；多图轮播先加载当前图，再补载相邻图。
- 卡片容器负责等比填充和视觉裁切；正文与查看大图保持完整构图。原图只允许在规定的故障回退链路或用户主动批量保存原图时请求。
- 不以固定 KB 体积作为上传或验收门槛；实际体积随源图内容变化，以既定派生规格和真实设备加载结果为准。

## 10. 合规与安全

P0 合规要求：

- 不出现后援会、粉丝团、应援、打榜等表达。
- 不做公开评论区。
- 不做公开社群互动。
- 广告不自动打断用户正常操作。
- 留言保存调用服务端文本检查：始终先检查拦截词；启用文本审核时，生产类环境使用微信文本安全接口且检测失败拒绝提交。当前仍允许后台关闭远程文本审核，关闭时非拦截词内容标为 `unchecked`；这是实现边界，见《已知暂缓事项》。
- 微信公众平台生成并审核的《小程序用户隐私保护指引》作为正式真源；小程序设置中的“隐私政策”直接调用 `wx.openPrivacyContract`，不再维护重复摘要页。
- 个人信息类型、第三方平台和处理用途只在微信公众平台隐私保护指引中维护，不再在小程序内额外制作独立清单页。
- 微信公众平台只填写当前版本实际调用的个人信息类型和对应用途；底层文件存储不额外作为微信信息类型申报，当前首页“保存原图”调用相册保存能力，声明须对应实际用途；未调用的剪贴板等能力不得照搬到指引中。
- 注销流程统一为：用户通过设置页显示的开发者邮箱申请，开发者核实后在 Admin 手动注销当前小程序账号。当前小程序的登录会话、独立数据和当前实例记录应删除；共享数据是否保留按账号对该数据范围的剩余归属判断：同一账号仍关联其他使用该共享范围的小程序时保留，否则删除该账号在该共享范围中的数据。不得影响其他账号或该账号仍归属其他小程序的数据。

安全要求：

- 正式环境 API 使用 HTTPS；开发环境允许本机 HTTP 调试。

## 13. 启动与配置机制

### 13.1 启动流程与兜底

- 小程序启动时由统一启动配置服务发起配置请求，首页与底部导航共用同一份答案；首页在首次请求降级后最多强制重试一次。
- 单次配置请求最多等待 2 秒；首次请求未取得 fresh 答案时自动重试一次。首页从冷启动开始独立计算 5 秒总时限，超过时限仍未取得有效配置时固定进入文章页，任何情况下不得出现无限空白页。
- 配置超时或失败时可读取按环境与 AppID 隔离的本地完整配置缓存（无缓存则用内置默认值）作为页面数据和导航的降级数据，但降级结果不得打开首页。
- 降级结果只用于当前启动放行，后续普通配置读取会自动发起新一代请求；迟到的答案必须先通过代数校验，不能覆盖新答案或污染缓存。
- 弱网等待期间显示统一加载态（`loading-state`）；迟到的新配置到达后只做校正广播，不重复触发已完成的启动。
- 用户在首页、文章、心笺、我的及其列表页下拉刷新时，先强制重新拉取一次启动配置，再刷新业务数据；配置失败不清空已有业务内容。

### 13.2 首页默认隐藏（审核 fail-safe）

- 代码内置默认值为「首页隐藏」：仅当服务器配置明确首页可见时才展示首页。
- 无缓存冷启动叠加弱网超时、失败或仅有缓存的最坏结果均落入文章页，而不是闪现首页导致审核风险；只有启动请求取得 fresh 答案且服务器明确 `home.visible=true` 时才展示首页。5 秒总时限由首页独立计时，不依赖配置请求是否自行结束。
- 固定兜底优先使用 `reLaunch('/pages/articles/articles?startupFallback=1')`，调用失败再使用 `switchTab('/pages/articles/articles')`。文章页收到迟到的 fresh 配置后只更新导航条，不把用户弹回首页。

### 13.3 三层配置

- **L1 代码内置默认**：随版本发布、100% 可靠、零网络依赖；首页默认隐藏、留言默认关、广告默认不展示等一律取保守方向。
- **L2 核心配置**：随启动请求下发，以紧凑载荷为目标；当前未在协议中强制 gzip 后 10KB 上限；含 tab 可见性、广告 ID 与广告配置、内容池绑定、存储配置、留言开关等「没有就无法正常运营」的小而稳定配置。
- **L3 文案包**：会规模增长的列表型文案（分享文案库、封面底图 URL 库、打卡前后文案池、手记提示语池），由独立接口 `GET /api/miniapp/copy-pack?version=N` 下发：启动门落定后后台静默加载，客户端携带本地缓存版本号，服务端未变更只回 `changed:false`（省流量），变更才回全量包；永不进启动门，加载失败由默认文案包兜底、用户无感。**（已实现，2026-09-08；home/config 等公开 payload 的 system 字段不再携带文案列表，shareSettings 亦不再随页面数据下发，均统一走文案包。配置请求全端唯一：启动门之外的数据空间复核（回前台）、登录、离线回放一律复用统一启动配置服务的答案，不再各自请求 /miniapp/config。）**
- **文案生效时机（2026-09-08 定稿）**：后台改文案后，正在浏览的页面保持不动，**下次进入页面 / 重新渲染时生效**（回前台版本校验有 30 秒节流）；不做运行时广播与当前页强制刷新。
- 文章、心笺等内容接口由页面自治加载，永不纳入启动门条件。

### 13.4 默认文案包与覆盖规则

- **两层默认文案（2026-09-08 定稿）**：
  - **小程序内置默认包**：`utils/default-copy.js`，随版本发布、零网络依赖，仅在网络失败 / 服务端未返回时兜底；常规随机/轮换位 2 条、固定位 1 条，分享标题和封面文案在文案、音频、图册三个池中各保留 1 条兜底文案，内容由产品侧逐条确认定稿（2026-09-07）。
  - **后台默认文案**：服务端 `defaultSystem` 预填同一套定稿文案，新建小程序实例即存在；下发给小程序后**以自定义配置的形式生效**（在小程序看来与后台手动配置无区别）。后台编辑框预填显示，管理员可直接修改。
  - 常规系统文案两层内容保持一致，调整定稿文案须同步修改客户端 `utils/default-copy.js` 与服务端 `admin-settings.store.js` 的 `defaultSystem` 及本章。全局分享设置的后台初始库每类含 2 条标题和 2 条封面文案，客户端各池仅保留 1 条独立兜底文案；两者不要求逐条相同。
- **显式清空**：后台把文案列表保存为空（编辑框留空）时，服务端**原样下发空数组**、不回填默认值；客户端取到空列表后回落内置默认包，绝不与默认合并。
- 分享文案按内容类型分池：手记（text）、图册（album/image）、音频（audio），每池含分享标题与封面文案；另有公共分享标题兜底与分享底图 URL 库。
- 文案包下发通道：客户端取值顺序为「运行时文案包（后台配置）→ 代码内置默认包」；文案包版本号由文案列表版本与分享设置版本组成，格式为 `${copyVersion}.${share.version}`。小程序文案列表或全局分享设置任一**内容实际变化**时递增（重复保存相同内容不递增）。分享封面样式、封面文案开关等分享设置整体随文案包的 `share` 字段下发（底图已解析为可访问 URL）。客户端本地缓存使用按环境与 AppID 隔离的键（`copy-pack-cache-v2:<env>:<appId>`），版本号作为值存储在缓存内。

### 13.5 活跃访问记录

- `App.onShow` 保留已有会话时的静默登录复核，任意页面回前台均适用，复用已有的在途登录请求。首次只浏览时不为统计主动登录，不新增独立访问上报。
- 页面不等待复核结果，失败不弹窗、不影响继续浏览；下次回前台继续复核。
- 后台复用成功登录和已登录首页请求统计活跃，按实例与账号将 60 秒内重复请求合并一次；周活及访问人数再按账号去重，日期使用北京时间。
- 现有小程序代码无须为后台分组和这些统计改动重新上传。首次只浏览、未触发登录的访问尚不计入账号访问数据。
